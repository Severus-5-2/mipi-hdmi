# MIPI-HDMI 实时视频图像处理系统

基于安路 PH1P35 FPGA 的实时视频图像处理系统：MIPI 摄像头采集 → ISP 图像处理 → DDR3 帧缓存 → 图像处理 → HDMI 显示。
支持 4 种图像处理模式通过拨码开关实时切换，并具备完整的 ISP 链路（去马赛克、自动白平衡、黑电平扣除、Gamma 校正）与可现场调节的曝光/增益控制。

## 硬件平台

| 项目 | 型号 |
|:---|:---|
| FPGA | 安路 PH1P35（PH1P35MDG324） |
| 开发板 | 康芯 HX1P35A |
| 摄像头 | SC520CS（RAW10，2-Lane MIPI，828 Mbps/Lane） |
| 输入分辨率 | 1280×720@60（Sensor 内部 VBIN+HSUB 直出真实 720p） |
| 显示 | HDMI 1280×720@60 |
| 缓存 | 片外 DDR3，乒乓帧缓存 |

## 功能特性

### 1. 四模式实时切换

拨码开关 SW1/SW2 实时切换 4 种图像处理模式：

| 模式 | SW2 | SW1 | 功能 |
|:---:|:---:|:---:|:---|
| 00 | 上 | 上 | 原图（RGB 彩色） |
| 01 | 上 | 下 | 灰度化 |
| 10 | 下 | 上 | 二值化 |
| 11 | 下 | 下 | Sobel 边缘检测 |

> 开关物理位置：SW1 为左数第 4 位，SW2 为左数第 3 位（板上顺序 4,3,2,1,5,6）。
>
> **电平约定（实测确认）：拨上 = 0，拨下 = 1**（与常见上拉接法相反，注意别搞反）。
> 代码里 `S_mode_sel = {I_sw2, I_sw1}`，与下表一一对应。

### 2. ISP 图像质量处理

- **去马赛克（Demosaic）**：RAW10 → RGB888
- **自动白平衡（AWB）**：灰度世界法，帧级统计 R/G/B 均值，除法器求增益后逐像素校正
- **黑电平扣除（BLC）**：限幅扣除，避免无符号下溢造成暗部亮噪点
- **Gamma 校正**：256×8 查找表，γ = 1/2.2，把线性域数据转换到显示域，解决"画面发暗、雾感、颜色闷"

### 3. 曝光与增益控制

- 曝光固定为满帧 1991（单位 1/2 行，约 16.6 ms，即手册规定的上限 2×VTS-9）
- 增益阶梯覆盖 **1x ~ 126x**（模拟 32x × 数字粗 2x × 数字细 1.969x），可由板上两个按键实时调节

## 系统架构

```
SC520CS (MIPI CSI-2 2-Lane RAW10)
      │
      ▼
  CSI 解包 → RAW10 解包
      │
      ▼
  Demosaic（去马赛克）
      │
      ▼
  AWB（灰度世界自动白平衡）
      │
      ▼
  DDR3 帧缓存（乒乓）
      │
      ▼
  BLC + Gamma 校正          ← 显示域，算法链之前，保证各模式延迟一致
      │
      ├──► 灰度化 ──► 二值化
      │
      └──► Sobel 边缘检测
                │
                ▼
        4 选 1 MUX（拨码开关选择）
                │
                ▼
        OSD 字符叠加 → HDMI TX → HDMI 显示
```

## 关键算法

### 图像处理

- **灰度化**：`Gray = (R×77 + G×150 + B×29) >> 8`
- **二值化**：固定阈值判定（`THRESHOLD` 参数可配）
- **Sobel**：3×3 窗口梯度，幅度 `|Gx| + |Gy|` 超过 `EDGE_TH` 判为边缘

### ISP

- **黑电平扣除**：`out = (in > BL) ? (in - BL) : 0`，`BL_LEVEL` 默认 16（对应 RAW10 域的 64）
- **Gamma 校正**：`out = 255 × (in/255)^(1/2.2)`，用 256×8 查找表实现，三通道各一份 ROM，相对输入延迟 1 拍
- **AWB**：帧内累加 R/G/B 求和 → 除法器求 `G/R`、`G/B` → 逐像素乘增益，G 通道保持原值

### 增益阶梯（SC520CS）

| 寄存器 | 含义 | 取值 |
|:---|:---|:---|
| `0x3e09` | 模拟增益 | `00`=1x `08`=2x `09`=4x `0B`=8x `0F`=16x `1F`=32x |
| `0x3e06` | 数字粗增益 | `00`=1x `01`=2x |
| `0x3e07` | 数字细增益 | `80`=1x … `FC`=1.969x（精度 1/32） |

增益控制字 `I_AG` → 总增益速查：

| `I_AG` | 总增益 | 说明 |
|:---:|:---:|:---|
| 16 | 1x | 最低 |
| 144 | 16x | 旧默认值（画面明显偏暗） |
| 176 | 32x | 纯模拟最大，噪声最小 |
| **207** | **63x** | **当前默认值** |
| 239 | 126x | 系统上限，噪点明显 |

## 按键操作（现场调试，无需重新编译）

按键为**低有效**（按下 = 0）：

| 按键 | 功能 |
|:---|:---|
| `I_button[1]` | 增益 + |
| `I_button[0]` | 增益 - |

增益按键每 32 ms 变化 1 级。从默认 207 加到上限 239 约长按 1 秒，减到 176 约 1 秒。

## 可调参数速查

| 参数 | 位置 | 默认值 | 作用 |
|:---|:---|:---|:---|
| `EN_GAMMA` | `gamma_lut` 实例化 | 1 | 0 = 旁路 Gamma，用于 A/B 对比 |
| `EN_BLC` | `gamma_lut` 实例化 | 1 | 0 = 关闭黑电平扣除 |
| `BL_LEVEL` | `gamma_lut` 实例化 | `8'd16` | 画面发灰调大，暗部出现亮噪点调小 |
| `GAMMA` | `gen_gamma_lut.py` | 2.2 | 画面偏暗改 1.8，发灰白改 2.4（改后重跑脚本） |
| `r_ag_set` | `ae_set.v` | 207 | 上电默认增益控制字 |
| 增益上限 | `ae_set.v` | 239 | 按键可调范围的上界 |

## 编译与下载

1. 用安路 TangDynasty (TD) 打开 `td_project/camera_to_dsi_display.al`；
2. 确认工程源文件清单中包含 `user_source/hdl_source/gamma_lut.v`（若用 `sc520_ae_fix/` 里的替换文件，
   需先移除旧的 `uics520_cfg/SC520GainTbl.v` 与 `uiisp_beta/ae_set.v` 再加入新文件，避免模块重复定义）；
3. 综合 → 布局布线 → 生成 bit 流 → 下载。

## 版本记录

| 版本 | 内容 |
|:---|:---|
| v1 | 基础工程：原图 / 灰度 / 二值 / Sobel 四模式 + 拨码切换 |
| v2 | ISP 图像质量修复：新增 `gamma_lut.v`（黑电平扣除 + γ=1/2.2 Gamma 查表），替换原 `brightness_gain` |
| v3 | 增益修复：重构 `SC520GainTbl` 把数字增益纳入阶梯（上限 32x → 126x，全程单调），`ae_set` 默认增益 16x → 63x |

### v3 修复说明

原先 `uics520reg_720p60.v` 初始化表里写的是 126x（32x 模拟 + 2x 数字粗 + 1.969x 数字细），
但上电完成后 `ae_set` 会强制下发一次曝光/增益，经旧 `SC520GainTbl` 查表后实际只剩 **16x**，
画面比应有亮度暗 **7.9 倍（约 18 dB）**。v3 通过重构增益阶梯表 + 提高默认增益解决该问题，
并使两个按键可以现场扫描 1x ~ 126x 全范围。

## 已知问题与后续计划

- **黑电平扣除位置**：目前 `BLC` 位于显示域（AWB 之后），标准 ISP 顺序应为 BLC → Demosaic → AWB。
  各通道黑电平不一致时会影响 AWB 统计精度，后续计划把扣黑前移到 AWB 之前。
- **自动曝光（AE）**：当前为固定满帧曝光 + 手动增益，场景切换时需要手动调节；
  计划增加帧均值统计实现自动曝光。
- **色彩饱和度**：暂无 CCM 与饱和度增强，后续计划增加饱和度调节模块。
- **降噪**：高增益下暗部有可见噪点，视情况增加轻量降噪。
