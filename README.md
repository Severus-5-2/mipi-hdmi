# MIPI-HDMI 实时视频图像处理系统

基于安路 PH1P35 FPGA 的实时视频图像处理系统：MIPI 摄像头采集 → ISP 图像处理 → DDR3 帧缓存 → 图像处理 → HDMI 显示。
支持 4 种图像处理模式通过拨码开关实时切换，并具备较完整的 ISP 链路（黑电平校正、去马赛克、自动白平衡、Gamma 校正、色度降噪、饱和度增强）与可现场调节的增益控制。

在画质链路之外，**方案B 提供实时目标检测与跟踪**：YCbCr 双阈值颜色掩膜 → 游程法 4 连通域标注 → 帧末特征汇总（面积 / 包围盒 / 质心 / 颜色）→ 前 4 目标列表总线 → 画框 OSD 叠加。

## 硬件平台

| 项目 | 型号 |
|:---|:---|
| FPGA | 安路 PH1P35（PH1P35MDG324） |
| 开发板 | 康芯 HX1P35A |
| 摄像头 | SC520CS（RAW10，2-Lane MIPI，828 Mbps/Lane） |
| 输入分辨率 | 1280×720@60（Sensor 内部 VBIN+HSUB 直出真实 720p） |
| 显示 | HDMI 1280×720@60（像素时钟 74.25 MHz） |
| 缓存 | 片外 DDR3，乒乓帧缓存 |

## 功能特性

### 1. 四模式实时切换

拨码开关 SW1/SW2 实时切换 4 种图像处理模式：

| 模式 | SW2 | SW1 | 功能 |
|:---:|:---:|:---:|:---|
| 00 | 上 | 上 | 原图（RGB 彩色） |
| 01 | 上 | 下 | 灰度化 |
| 10 | 下 | 上 | 二值化 |
| 11 | 下 | 下 | Sobel 边缘检测 |

> 开关物理位置：SW1 为左数第 4 位，SW2 为左数第 3 位（板上顺序 4,3,2,1,5,6）。
>
> **电平约定（实测确认）：拨上 = 0，拨下 = 1**（与常见上拉接法相反，注意别搞反）。
> 代码里 `S_mode_sel = {I_sw2, I_sw1}`，与上表一一对应。

### 2. ISP 图像质量处理

- **黑电平校正（BLC）**：在 RAW10 域扣除传感器黑电平（`10'd64`），带限幅防止无符号下溢
- **去马赛克（Demosaic）**：RAW10 → RGB888（BGGR 阵列）
- **自动白平衡（AWB）**：灰度世界法，帧级统计 R/G/B 均值，除法器求增益后逐像素校正
- **Gamma 校正**：256×8 查找表，γ = 1/2.2，把线性域数据转换到显示域，解决"画面发暗、雾感、颜色闷"
- **色度降噪**：转 YCbCr 后**只对 Cb/Cr 做 3×3 可分离低通，亮度 Y 完全不动**，消除高增益下的彩色噪点且不损失清晰度
- **饱和度增强**：保持亮度 Y 不变、只放大色度分量（C−Y），解决"颜色发闷、色彩浓度不足"；带色度死区抑制灰色区噪点

### 3. 自动曝光（AE）与增益控制

闭环链路：**帧测光 → 与靶亮度比较 → 先调曝光、曝光到顶后再调增益**（画面偏暗时）；
**先降增益、增益到底后再降曝光**（画面偏亮时）。

- **测光**（`ae_meter`，像素时钟域）：逐帧统计 `Y = (77R + 150G + 29B) >> 8`，
  采用 **3×3 九宫格中央重点加权**（中心区权重 8×、边中区 2×、四角区 1×），
  解决逆光时全帧平均被背景亮区绑架、人物变成剪影的问题；
  保留 `METER_MODE` 参数，设 0 即退回全帧平均，方便上板 A/B 对比
- **控制**（`ae_set`，24 MHz 域）：误差越大步进越大；曝光步进与当前曝光值成比例（下限 8），
  增益为固定步进；命中死区 `|err| < 4` 不动作；每 3 帧才调一次
  （SC520CS 寄存器写入需 N+2 帧生效，`WAIT_FRAMES=3` 是防振荡的关键）
- 增益阶梯覆盖 **1x ~ 126x**（模拟 32x × 数字粗 2x × 数字细 1.969x），上电默认 63x（`I_AG=207`）
- **按键功能已改为调「靶亮度」**（范围 60 ~ 200，默认 120，单次按下 ±8），而不是直接调增益

### 4. 目标检测与跟踪（方案B）

在画质链路之外并行的一条**检测链**，输出目标列表供画框显示（详见 `doc/开发方案B-目标检测跟踪与运动检测.md`）：

- **颜色检测（`detect_zjy/detect_color_mask.v`）**：RGB → YCbCr 后按 **v2 曝光自适应判据**
  （方向 + 幅度 + 绿双轴门限 / 红蓝比值）输出二值掩膜 —— 相比 v1 的「Cb/Cr 固定双阈值」，
  它**对整体亮度缩放免疫**（低曝光不再漏检）。`I_color_sel` = `0/1/2` 取单色、`3` 取三色相或（多色同帧）。
  门限走 `common_defs.vh §5b` 的宏、顶层例化引宏（**不要写字面量**，会覆盖模块默认值）。
- **掩膜去斑（`detect_zjy/mask_despeckle.v`）**：水平窗（左右各 `HALF=4`、窗内命中 ≥ `KMIN=5`）
  + **跨 3 行 2/3 多数投票** + 保险条款。插在检测与连通域之间 —— 因为 `conn_label` 的 `NEG` 是
  「同帧最多 N 个连通域、**按扫描顺序先到先得**」，孤立噪点会**抢走名额**让真目标无框；
  去斑从源头清掉散点（噪声连通域 σ=8 时 12k → **0**，而实心目标 100% 保留）。
- **连通域标注（`common_base/conn_label.v`）**：行内游程（RLE）+ 行间 **4 连通**重叠判定
  + 内部展开深度 **`NEG=8`** 的等价表并查集（纯寄存器；`LABEL_MAX` 宏仍为 32）。
  另含 **`LMIN`**（单行游程最小长度，默认 8）：短游程整体忽略 ⇒ 噪点**不占 `NEG` 名额**。
  输出**每像素 label 流**（6 bit，0 = 无归属）与**帧末汇总**（紧凑编号 / 面积 / 包围盒 / 质心；
  质心在消隐期用 31 步移位-减法除法器算），并给出每个连通域的颜色分类 `cls`（优先级 红 > 蓝 > 绿）。
- **特征汇总（`common_base/conn_features.v`）**：汇总流按**面积降序取前 4**（插入排序擂台），
  经 `common_base/target_bus.v` 打成 **384 bit 目标列表总线**（4 槽 × 96 bit）。
- **几何形状分类（`detect_zjy/shape_class.v`，D5）**：从目标总线取 `area / bbox` 算**填充度**
  判方 / 圆 / 三角（方 f≥88% / 圆 72~88% / 三角 38~72%）。**零除法、零 DSP**
  （`f≥T%` 化为交叉相乘 + 移位加法；结果每帧只变一次 ⇒ 分时用 1 个乘法器算 4 槽）。
- **类别数量 OSD（`detect_zjy/osd_category.v`，D6）**：屏幕左上角两行
  `R:x B:x G:x`（颜色计数）/ `S:x C:x T:x`（形状计数）。自带 `R/B/G/S/C/T` 字母 ROM，
  数字与冒号**复用 `osd_char_lib.v`**（不动共享字库）。
- **画框 OSD（`track_box/rtl/box_draw.v`）**：按目标列表在屏上画框，并叠加屏心十字准星。

```
SC520CS (MIPI CSI-2 2-Lane RAW10)
      │
      ▼
  CSI 解包 → RAW10 解包 → BLC（RAW 域扣黑电平）
      │
      ▼
  Demosaic（去马赛克，BGGR）
      │
      ▼
  AWB（灰度世界自动白平衡）
      │
      ▼
  DDR3 帧缓存（乒乓）
      │
      ▼
  Gamma 校正（256×8 查表，γ=1/2.2）   ← 显示域，各算法分支之前，保证延迟一致
      │
      ├──► 色度降噪 ──► 饱和度增强 ──┐ ← 仅彩色原图通路（灰度/二值/Sobel 不经过）
      │                              │
      ├──► 灰度化 ──► 二值化 ────────┤
      │                              │
      └──► Sobel 边缘检测 ───────────┤
                                     │
                                     ▼
                        4 选 1 MUX（拨码开关选择）
                                     │
                                     ▼
                                     ▼
                        OSD 字符叠加 → HDMI TX → HDMI 显示
```

**AE 反馈环**（不参与像素数据流，走 SCCB 配置通道）：

```
显示前的 RGB 像素 ──► ae_meter（逐帧加权测光，像素时钟域）
                            │ Y_avg[7:0] + frame_toggle（异步握手）
                            ▼
                     ae_set（24 MHz 域）──► SCCB ──► SC520CS 曝光/增益寄存器
```

> `ae_meter` 与 `ae_set` 跨时钟域，已在 SDC 中用 `set_false_path` 约束该方向：
> 数据每帧更新后整帧保持静态 + `frame_toggle` 翻转握手 + 对端两级同步，异步协议是安全的。

> **排查提示**：`Gamma` 之后数据流分叉——灰度/二值/Sobel 三路直接从 `S_video_bright` 取数，
> 只有彩色原图通路才经过色度降噪与饱和度增强。因此**若灰度正常而彩色异常，问题必在这两个模块**。

**方案B 目标检测链**（与上面的四模式处理链**并行**，挂在显示域数据上）：

```
显示域 RGB ──► YCbCr + v2 曝光自适应判据 ──► 颜色掩膜
                                                │
                                                ▼
                     mask_despeckle（水平窗 + 跨 3 行 2/3 垂直投票）
                                                │  只放行"成片"像素，清掉孤立散点
                                                ▼
                          conn_label（4 连通 RLE-CCL 连通域标注，NEG=8 + LMIN=8）
                                                │ 每像素 label 流 + 帧末汇总
                                                ▼
                          conn_features（面积降序取前 4 → 384bit 目标总线）
                                                │
                        ┌───────────────────────┴───────────────────────┐
                        ▼                                               ▼
      box_draw（按目标列表画框 + 屏心十字）        shape_class → osd_category
                        │                          （几何分类 → 类别/数量 OSD）
                        └──────────► 叠加仲裁（坐标OSD > 框 > 类别OSD > 掩膜）──► HDMI 叠加
```

> ⚠ 检测链里 `conn_label` 的 `I_de / I_mask / I_pix_x / I_pix_y` **必须全部取自 `detect_color_mask` 的 `O_*`**，
> 四者严格同拍；**不可**改接 `hdmi_mixer` 侧的延时信号（延时对不上会导致整帧错位）。

## 关键算法

### 图像处理

- **灰度化**：`Gray = (R×77 + G×150 + B×29) >> 8`
- **二值化**：固定阈值判定（`THRESHOLD` 参数可配）
- **Sobel**：3×3 窗口梯度，幅度 `|Gx| + |Gy|` 超过 `EDGE_TH` 判为边缘

### ISP

- **黑电平校正**：在 RAW10 域执行 `(raw10 − 64) >> 2`，等价于 8bit 域扣 16。
  须在 Demosaic/AWB **之前**完成，否则各通道的 pedestal 会被灰度世界法算进白平衡增益，导致偏色与雾感
- **Gamma 校正**：`out = 255 × (in/255)^(1/2.2)`，256×8 查找表实现，三通道各一份 ROM，延迟 1 拍
- **AWB**：帧内累加 R/G/B 求和 → 除法器求 `G/R`、`G/B` → 逐像素乘增益，G 通道保持原值
- **色度降噪**：

    ```
    RGB ──► YCbCr ──►  ┌ Cb ── 3×3 可分离低通 [1 2 1]×[1 2 1]/16 ──┐ ──► YCbCr ──► RGB
             │         └ Cr ── 同上 ────────────────────────────────┘
             └── Y 完全不动（只做延时对齐），保证不糊边、不损失细节
    ```

    流水线 5 级（RGB→YCbCr / 水平滤波 / 行延时 BRAM / 垂直滤波 / YCbCr→RGB），单级 ≤4 级逻辑；
    色彩空间正反变换均加四舍五入（`+128 再 >>>8`），往返平均误差 0.78、灰阶零色偏。
    实测色度噪声 σ 降低约 2.16 倍
- **饱和度增强**：`Y` 保持不变，`C' = Y + (C − Y) × SAT_GAIN`，限幅 0~255；
  色度死区内的像素（`|C−Y| ≤ DEADZONE`）不做增强，避免放大灰色区域的彩色噪点

### 增益阶梯（SC520CS）

| 寄存器 | 含义 | 取值 |
|:---|:---|:---|
| `0x3e09` | 模拟增益 | `00`=1x `08`=2x `09`=4x `0B`=8x `0F`=16x `1F`=32x |
| `0x3e06` | 数字粗增益 | `00`=1x `01`=2x |
| `0x3e07` | 数字细增益 | `80`=1x … `FC`=1.969x（精度 1/32） |

系统最大总增益 = 32 × 2 × 1.969 ≈ **126x**。增益控制字 `I_AG` → 实际增益速查：

| `I_AG` | 总增益 | 说明 |
|:---:|:---|:---|
| 16 | 1x | 最低 |
| 144 | 16x | 修复前的默认值（画面明显偏暗） |
| 176 | 32x | 纯模拟最大，噪声最小 |
| **207** | **63x** | **当前默认值** |
| 239 | 126x | 系统上限，噪点明显 |

## 按键操作（现场调试，无需重新编译）

按键为板载 **KEY1(D5) / KEY2(A9)**，低有效（按下 = 0，约束里已设 `PULLTYPE = PULLUP`）：

| 按键 | 引脚 | 功能 |
|:---|:---|:---|
| `I_button[1]` | KEY2 / A9 | 靶亮度 + （画面变亮） |
| `I_button[0]` | KEY1 / D5 | 靶亮度 − （画面变暗） |

- **单按一次 ±8**（按下沿触发），长按每 32 ms 再 ±1 做微调；靶亮度范围 60 ~ 200，默认 120。

### v6 修复说明（黑电平一次都没扣）

`isp/raw10_unpacket_2lane.v` 的 `I_camera_black_level` 端口虽然声明了、顶层也接了 `10'd64`，
但**活跃代码里从未使用**——那 4 行减法躺在 `/* ... */` 注释块（约 141~233 行）里；
而 `gamma_lut` 的 `EN_BLC` 又因为"已前移到 RAW 域"被置 0。**结果整条链路一次黑电平都没扣。**

SC520CS 的 pedestal（10bit 域 64 = 8bit 域 16）经 AWB 后送进 Gamma，而 Gamma 对暗端强放大
（`LUT[16] = 72`），于是最黑的地方被抬到 ~72 灰——这就是"雾感 / 发灰 / 对比度低"的真根因。
它同时拖累了 AE：`Y_avg` 里混着这块抬升量，AE 误以为画面够亮就不加曝光。

修复时必须**先比较再减**：10bit 无符号下 `63 − 64 = 1023`，右移 2 位就是 **255 白点**，
暗部会炸出一片亮点，比不扣更糟。

> 排查经验：同名 `.v` 文件在本工程里散落多处（`raw10_unpacket.v`、`raw10_unpacket_2lane.v`、
> `csi_unpacket_2lane.v` 都有副本），**只有 `.al` 工程清单里引用的那份才会被编译**。
> 改代码前务必先 `grep *.al` 确认生效文件（本例是 `isp/raw10_unpacket_2lane.v`），否则改了没效果。

### v6 AE 务实调试笔记

### v4 → v4.1 时序修复（-1.7 ns 违例）

初版 `sat_enhance` 把整套组合逻辑（3 个亮度常数乘法 + 3 个 10×9 有符号色度乘法 + 移位 + 加 Y + 双重限幅
≈ 8 级）压在 74.25 MHz 的同一拍内，导致 `gamma ROM → sat_enhance` 路径 Slack −1.704 ns。
v4.1 重写为**两级流水**（级 1 算 Y/色差/死区标志并打拍，级 2 乘增益/移位/限幅后输出），
单级逻辑降到 4 级以内；关键技巧是**只寄存 1 bit 的「是否彩色」标志而不寄存增益值**，
保证 `SAT_GAIN` 仍是编译期常量、被综合器优化成移位加（不占 DSP）。
用 Python 逐点比对 50653 个采样，与旧版**零差异**。

### v5 黑电平前移

原先黑电平在显示域（`gamma_lut` 的 `EN_BLC`）扣除，位于 AWB **之后**。
标准 ISP 顺序应为 BLC → Demosaic → AWB，否则各通道 pedestal 会被灰度世界法算进白平衡增益，
造成全局偏色（实测偏紫）与雾感。v5 改为在 RAW 域扣除（接上一直悬空的 `I_camera_black_level`
端口），并把 `gamma_lut` 的 `EN_BLC` 置 0 **防止重复扣除**——这两处必须成对修改。

### v5 → v5.2 降噪模块的两次定点 BUG 修复

| 版本 | 现象 | 根因 | 修复 |
|:---|:---|:---|:---|
| v5.1 | 彩色模式几乎全黑（闪光灯照射也无反应），灰度正常 | YCbCr→RGB 时把「Y + 系数×色差」**整体** `>>>8`，亮度被除以 256（中性灰 Y=128 输出成 1） | 只对乘积项除 256，Y 单独相加 |
| v5.2 | 亮度恢复正常但满屏饱和蓝/黄椒盐噪点，灰度正常 | **Verilog 部分选择永远无符号**：`r_div[9:0]` 使整个表达式退化为无符号运算，负色差被零扩展（−180 → +844），通道被随机砸到 0/255 | 去掉 `[9:0]`，直接让两个 signed 向量相加 |

两次均只修改 `denoise_fix/chroma_denoise.v`，顶层与其它文件不变。
v5.2 通过比特级 Python 模型验证：往返平均误差 0.78、256 级灰阶零色偏、噪声场景下通道饱和率 0%（BUG 版为 67.2%）。

- **雾感 / 发灰**：v6 修复了黑电平完全没扣的 BUG，暗部不再被 Gamma 抬到 ~72 灰（详见 v6 修复说明）。
- **【方案B】目标检测链**：v7 完成 D1~D4（颜色掩膜 → 连通域 → 特征汇总 → 目标总线 → 画框 OSD），位级对拍全通过。
  后续 D5+：伪彩叠加（用 `O_label` 流，需同步延一行）、`osd_coord` 接真实主目标质心、框色随 `cls` 联动。

### 待办（见 `doc/开发方案A-图像质量与风格化.md`）

- **Sobel 噪点（当前最扎眼）**：室内高曝光时边缘图满是椒盐白点。
  机理：AE 加曝光/增益 → sensor 噪声抬高 → Gamma 再放大暗噪声 → **Sobel 是高通，噪声正好落在通带** →
  越过固定阈值 `EDGE_TH=130`。方案 A 的 **A3（3×3 高斯预平滑）+ A4（阈值自适应）** 专门治它；
  预计做法：新建 `gauss_smooth.v`（2 块行缓存，`[1 2 1 / 2 4 2 / 1 2 1] >> 4`），
  阈值改为与 AE 当前增益联动（增益高 → 阈值升），并加 `TH`、`TH−32` 滞回让边缘连贯。
- **色相偏差（缺 CCM）**：NIR/光谱响应差异导致颜色发闷、偏绿，**Gamma 之前插 3×3 色彩校正矩阵**（A2）。
  注意每行系数和必须 = 256，否则白纸会偏色。
- **锐化缺失**：画面"不清楚"很大程度是缺锐化，比升分辨率便宜得多（A5 USM）。
- **直方图均衡**：赛题原文点名（A6），必须带 α 混合，否则暗光噪声会爆炸。
- **亮度噪点**：高增益（63x+）暗部仍有可见噪点。`chroma_denoise` 已消除大部分**彩色**噪点，
  残余的是**亮度**噪声，属物理极限；治本靠 AE 降增益，必要时加轻量亮度降噪（会轻微糊边，慎用）。
- **饱和度增强会放大色度噪点**：这是原理决定的，应在色度降噪之后使用（当前顺序已满足），
  但仍不建议过度提高 `SAT_GAIN`。

## 开发注意事项（经验总结）

1. **时序预算**：74.25 MHz 预算仅 13.33 ns，单个像素时钟拍内约能容纳 4~6 级 LUT。
   在视频流水线插入新处理模块时，宁可在模块内部多打拍（横向偏 1 像素肉眼不可察），
   也不要把长组合逻辑压在一拍里。
2. **保持参数为编译期常量**：增益类 `parameter` 一旦被打进流水寄存器变成运行时变量，
   综合器就无法做常量传播，会生成通用乘法器/DSP 并且逻辑级数上升。
3. **定点运算的量纲**：缩放系数的除法（如 `>>>8`）只能作用于「已乘过系数的项」，
   绝不能把未缩放的量一起除。
4. **Verilog 部分选择永远无符号**：`signed_vec[9:0]` 是 unsigned，含它的表达式整体退化为无符号，
   负数会被零扩展成大正数。需要保留符号时应整体相加或用 `$signed()` 显式包裹。
5. **验证模型必须比特级镜像 RTL**：功能级的 Python 模型容易漏掉符号扩展、位宽截断类 BUG。
   凡含 signed 运算的模块，验证时应模拟位宽环绕、补码解释与 `>>>` 行为。
6. **排查铁律**：灰度/二值/Sobel 正常而彩色异常 ⇒ 问题必然出在「只有彩色通路才经过」的模块。
