## 使用说明

- **冻结含义**：本表中任何信号的**名称、位宽、方向、时钟域、有效电平、取值域**一经确认，改动必须**双方同意**，并在本文件末尾追加版本记录。
- **对齐纪律**：两人各自的模块在**此表基础上**对接，不靠口头传、不靠"我以为"。
- **命名前缀约定**：
  - `S_` = S 全局信号（顶层分发）
  - `I_` = 模块输入；`O_` = 模块输出
  - `*_zjy` = 张金艺私有域；`*_zmc` = 张铭晨私有域
- **位序约定**：总线上**低位在前**（`[n:0]` 中低 bit 是有效位），打包 `{高, ..., 低}` 与工程现有风格一致。

### ⚠ 1.1 坐标与帧末的强制约定（**最容易出事的地方**）

| 项 | 冻结约定 |
|:---|:---|
| 计数条件 | **仅 `de` 有效时计数** |
| 帧起始 | **`vsync` 上升沿（场消隐期）→ `x=0, y=0`**（★ 见下方说明，不用 user 清零） |
| 换行 | `de && last` → `x=0, y=y+1` |
| 列递增 | `de && !last` → `x=x+1` |
| 消隐期行为 | **`vsync` 上升沿（场消隐期）归零；`de` 无效期间保持**（★ 不可改为「de 无效时保持不动」，否则首行偏移会回来） |
| 帧末锁存 | 方案B §4：**帧界脉冲锁存本帧结果**。⚠ 本工程 `S_frame_done` 取自 **`user`**（帧首有效像素），**不是** `vsync` 上升沿；坐标归零用 `vsync`、结果锁存用 `frame_done`，两者分工见 §2 |
| 位宽 | `x` 需覆盖 0~1279 → **11 bit**；`y` 需覆盖 0~719 → **10 bit** |
| **★ 消费者采样时刻**（2026-10-14 新增） | 任何读 `S_target_bus` 的消费者，其**采样首拍必须 ≥ 总线锁存拍（`S_det_fdone`）**；**或比它早 ≥14 拍**（则读到完整上一帧，整体滞后 1 帧，可接受）。<br>⚠ **落在「早 2~13 拍」窗口内会静默串帧** —— 对"一拍读一个槽"的消费者（`target_assoc` / `shape_class` / `osd_category`）尤其致命。<br>实测：`detect_zjy/tb_shape_class_frame_align.v` + 张铭晨 `tb_frame_latch_early.v`，**双方独立得出同一窗口**。<br>⇒ **因此 `pix_coord_gen` 升级必须与顶层 3 处 `I_frame_done` 改接 `S_det_fdone` 同时做**（新版 `O_frame_done` 在帧首，比锁存早 ≈3 拍）。 |

> ★ **为什么用「场消隐期归零」而不是「user 优先清零」**（2026-10-10 位级验证）：
> `hdmi_mixer` 内建计数器采用「user 优先清零」，位级审计证明有两个副作用 ——
> ① 首行（`y=0`）整行 `S_x` 比真实列号**小 1**；② 帧首像素采到上一帧残留 `S_y=720`。
> `pix_coord_gen.v` 改用场消隐期归零，**无这两个偏移**。
> ⚠ 若有人按旧口径改回「保持不动」，这两个偏移会**重新出现**。

> 🔴 **已解决（2026-10-10 对账后）**：方案B §1.3 要求公共坐标由队长在 top 生成；张金艺 `detect_color_mask.v` 曾内部自建 `x_cnt/y_cnt`，**现已改造为接入公共坐标**，内部计数器删除。
> **统一实现**：全队使用**张铭晨**的 `user_source/hdl_source/track_box/rtl/pix_coord_gen.v`
> （**场消隐期归零**，已修掉「user 优先清零」的首行偏移 + 帧首残留两个副作用；自带 `_1d`/`_2d` 延时输出）。
> ⚠ `common_base/pix_counter.v` **已删除**，不再使用。
> ⚠ **延时对齐**：`pix_coord_gen` 输出到 `_2d`（2 拍）；`detect_color_mask` 内部流水 3 拍，
> 需在检测模块输入端**自行补 1 级寄存器**凑满 3 拍，否则坐标比掩膜早 1 拍、整帧错位。

## 2. 张金艺 → 张铭晨：目标列表总线（§4：艺→晨）

**接口名**：`S_target_bus`（顶层信号名，实例间可用 `I_target_*` / `O_target_*`）

**时序**：**帧界锁存**，`S_frame_done` 锁存；本帧结果在**下一帧期间**保持稳定，供张铭晨随时采样。

> ⚠ **`S_frame_done` 到底是什么**（2026-10-11 一致性复查更正）：它是**对齐后的 `user` 脉冲，落在帧首有效像素**，
> **不是 `vsync` 上升沿**。坐标计数器的归零点才是 `vsync` 上升沿（§1.1）——**两者差着整个场消隐期，不要混**。
> 本工程 `S_frame_done` 取自 `detect_color_mask.O_frame_done`（= 内部 `d3_user[1]`）。

> 📌 **v1.5 补记（内部结算脉冲，不跨人）**：帧末"汇总/结算 FSM"（跑约 2150 拍，落在场消隐期）需要一个
> **与帧首 user 不同的触发点**。冻结约定：**此结算触发由模块内部产生，不占用跨人接口**。
> - 张金艺：`conn_label` 内部检测「最后一行结束」`frame_end` 触发汇总 FSM；
> - 张铭晨：`conn_label` 产 `O_frame_end`（`I_vsync` 上升沿同拍）给内部 `conn_features`（解法 A）。
> ⇒ 两条路的**对外 `S_frame_done` 仍为工程原义（对齐 user）**，集成方无需转换、接口零改动。

**深度**：**4**（最多 4 个目标，方案B §3.1 明确）

### 2.1 单目标字段定义（每目标 86 bit）

| 字段 | 位宽 | 取值域 | 说明 |
|:---|:---:|:---|:---|
| `valid` | 1 | 0/1 | 该槽位是否有目标 |
| `cls` | 2 | **0=红 1=蓝 2=绿 3=未分类** | 分类结果（★ 编码以 `common_defs.vh` 的 `CLS_*` 宏为唯一依据） |
| `cx` | 11 | 0 ~ 1279 | 质心 x（消隐期算出） |
| `cy` | 10 | 0 ~ 719 | 质心 y |
| `xmin` | 11 | 0 ~ 1279 | 包围盒左边界 |
| `xmax` | 11 | 0 ~ 1279 | 包围盒右边界 |
| `ymin` | 10 | 0 ~ 719 | 包围盒上边界 |
| `ymax` | 10 | 0 ~ 719 | 包围盒下边界 |
| `area` | 20 | 0 ~ 921600 | 面积 Σ1（1280×720 = 921600，需 20 bit） |

位宽小计：`1 + 2 + 11 + 10 + 11 + 11 + 10 + 10 + 20 = 86 bit`

> 为便于跨模块传递与后续扩展（如加 `fill_ratio`、`aspect`），**建议打包为 96 bit 对齐**（补 10 bit 保留位）。

### 2.2 总线整体

| 信号 | 位宽 | 说明 |
|:---|:---:|:---|
| `S_target_valid_cnt` | 3 | 本帧实际有效目标数（0~4） |
| `S_target_bus` | **96 × 4 = 384** | 4 个目标槽位，每槽 96 bit |

> 💡 **打包/解包统一走 `common_base/target_bus.v`**，避免两人各写一套位域拼接。

> 📌 **v1.5 补注（`I_pack_end`，内部实现差异，不跨人）**：
> 若实现采用「`conn_features` → `target_pack` **两模块分立**」（如张铭晨），
> 则 `target_pack` 需要显式 `I_pack_end` 脉冲判流结束（消隐期内特征之间有间隔拍，**不能用 `I_cv_valid=0` 判**）。
> 若采用**帧内单模块擂台**（如张金艺 `conn_features.v` 内直接排序打包），则**不需要** `I_pack_end`。
> ⇒ 二者是内部实现自由，**`S_target_bus` 接口不受影响**。

### 2.3 排序约定（必须冻结）

**4 个目标槽位按 `area` 从大到小排列**，`area = 0` 的槽位 `valid = 0` 且排在有目标之后。

> 理由：张铭晨的跟踪做最近邻匹配时，如果两个人都默认"槽位顺序 = 面积降序"，匹配逻辑可以大幅简化；若顺序不定义，跟踪会出现"框跳到另一个目标"的观感 BUG。

**两条补充约定（2026-10-10 双方确认）：**

1. **面积相同时的确定序**：再按 `xmin` **升序**排列；若仍相同，再按**紧凑 `label` 升序**兜底（`conn_features.v` 已实现），保证排序结果确定（否则同一帧两次综合可能得到不同顺序）。
2. **排序只保证同一帧内**：**跨帧对应关系由消费方（张铭晨）用 `cls` + 位置自行关联，不依赖槽号稳定。**
   即：槽号 `k` 在相邻帧之间不保证指向同一目标。

### 2.4 无目标时的行为

| 情况 | 冻结行为 |
|:---|:---|
| 本帧无任何目标 | `S_target_valid_cnt = 0`，所有槽位 `valid = 0`（**其余字段必须清零**，不留上帧残留） |
| 目标数 < 4 | 空槽位 `valid = 0` 且**所有字段清零** |
| 低于最小面积门限 | 视为无目标（不占槽位） |

> 📌 **v1.5 冻结：最小面积门限 = `16`**（双方统一；`conn_label.MIN_AREA` = `target_pack.AREA_MIN` = 16）。
> 已落 `` `define MIN_AREA 16 ``（`common_defs.vh` §5 label 常量旁），`conn_label` 参数默认值与顶层实例均**引用该宏**，实现"值同源、不再分叉"。
> 低于 16 的连通域视为噪声，不进入目标列表。**对拍时两边必须同一门限**，否则"哪些小目标入选"会不同。

## 3. 张金艺 → 张铭晨 / 队长：连通域 label（§4：艺→晨→郭）

**接口名**：`S_label_*`

> ★ **归属澄清（2026-10-10）**：连通域由**张金艺**产出（开发方案B §2.2 归张金艺 D2–D4）。
> 数据链路：**艺（产 label）→ 晨（跟踪/关联）→ 郭（区域填充伪彩）**。
> `common_defs.vh` 早期注释误写为「晨 → 郭」，已更正。

方案B §4 注明："**连通域每像素 label 输出** → 我（郭）拿它做区域填充伪彩着色"，且 §3.2 注明运动检测**复用甲的连通域模块**。

### 3.1 每像素 label 流

| 信号 | 位宽 | 时钟域 | 说明 |
|:---|:---:|:---|:---|
| `O_label` | **6** | pixel | 当前像素所属连通域编号 |
| `O_label_valid` | 1 | pixel | 该像素是否属于任何连通域（等价于掩膜） |
| `O_label_de` | 1 | pixel | 与 label 对齐的 de |
| `O_label_pix_x` | 11 | pixel | 与 label 对齐的 x（**必须用公共 `S_pix_x` 延时对齐**） |
| `O_label_pix_y` | 10 | pixel | 与 label 对齐的 y |

### 3.2 label 编号规则（**必须冻结**）

| 项 | 冻结约定 |
|:---|:---|
| 编号起点 | **`0` 表示"无归属"**；有效 label 从 **`1`** 开始 |
| 是否连续 | 帧内**连续**（不等价合并后，重新紧凑编号 1,2,3,...） |
| 最大数量 | **32**（方案B §2.2：等价表深度 32，用 6 bit 表示，取值 0~32） |
| 帧内稳定性 | 同帧内同一连通域 label 不变；**帧间不保证一致**（跨帧关联由张铭晨的跟踪负责） |
| 与目标列表关系 | `target_bus` 的槽位 = 按 `area` 降序的连通域；**label 与槽位不是同一套编号**，需转换 |

> 🔴 **这条是合板最大雷区**：如果张铭晨的 label 从 0 起、张金艺的从 1 起，或者一方做了紧凑重编号另一方没有，**画的框会全部错位一整个目标**。所以必须写死。

> 📌 **v1.5 补记：`raw label 池` ≠ `连通域上限`——两个独立的数，别混**
> | 概念 | 值 | 含义 |
> |:---|:---:|:---|
> | **连通域数量上限** | **32** | 输出 `O_label`/紧凑编号的上限（6 bit） |
> | **raw label 池** | **512** | 内部临时编号池，须 ≥ 单行最大游程数（棋盘格最坏 640，取 512 为工程折中） |
> ⇒ 池满时超出的游程只保留统计（降级行为）；两者混用会写错状态机边界。

### 3.3 消隐期输出

帧内像素流结束后，`vsync` 消隐期输出该帧的**连通域汇总**（面积/Σx/Σy/bbox），供 `conn_features.v` 使用。此段为**模块内部**，跨人不接口，但需保证：**下一帧 `de` 有效前必须把累加器清零**。

### 3.4 `conn_label` 的**输入**补充（2026-10-11，不影响 label 语义）

| 端口 | 位宽 | 说明 |
|:---|:---:|:---|
| `I_color` | 2 | **新增（输入）**：该像素颜色类别（`CLS_*`），与 `I_mask` 同拍。仅供分类，**不参与连通判定**。 |
| `O_cmp_cls` | 2 | **新增（内部汇总流）**：`conn_features.v` 打包 `target_bus.cls` 用；全程未知 = `2'b11`。 |

> ⚠ **对张铭晨（运动检测）的影响**：复用 `conn_label` 做运动检测时，
> `I_color` **直接接 `2'b11`（`CLS_UNKNOWN`）** 即可，行为退化为「未分类」，其余完全不变。
> 运动检测不需要颜色，不必接颜色通路。
>
> **分类规则**：每连通域取「首个被指派时的已知色」；等价合并时颜色沿并查链向根传播。
> 上游单像素判决优先级为 **红 > 蓝 > 绿**（在 top 编码 `I_color` 时定死）。
> 前提：同一连通域内颜色一致（演示目标各占一色）。

### 3.5 汇总流 → 目标列表的转换（`conn_features.v`）

`conn_label.O_cmp_*`（内部汇总流）由 **`common_base/conn_features.v`** 消费，完成
「按 `area` 降序取前 4」+「`target_pack` 打包 384 bit」，即 §2 的 `S_target_bus`。
排序规则见 §2.3；空槽处理见 §2.4。**两侧都不要再自写一套排序或位域拼接。**

### 3.6 顶层集成（2026-10-11，`design_top_wrapper.v`）

| 项 | 约定 |
|:---|:---|
| 链路 | `detect_color_mask` → `conn_label` → `conn_features` → `S_target_bus` → `box_draw` |
| `detect_color_mask.I_color_sel` | 改 **`2'd3`**（三色取或，多色同帧） |
| `conn_label` 输入源 | **全部取自 `detect_color_mask` 的 `O_de / O_mask / O_pix_x / O_pix_y / O_frame_done`**（严格同拍）。⚠ 禁止改接 `S_hdmi_de / S_pix_x_2d` |
| 颜色编码 | `I_color = r ? CLS_RED : b ? CLS_BLUE : g ? CLS_GREEN : CLS_UNKNOWN`（优先级 红>蓝>绿，**唯一判决点**） |

> §3.1~§3.5 的既有冻结项（`O_label` 语义、编号起点、4 连通、`cls` 编码）**一律未变**。
