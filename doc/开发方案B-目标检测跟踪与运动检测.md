## 1. 共同基础（D1，两人一起做）

### 1.1 取数位置与颜色空间

- 从 `S_video_sat`（Gamma / 降噪 / 饱和度增强后的 RGB888，74.25MHz 域）取数。
- 颜色判定**必须转 YCbCr 再判**（转换系数直接复用 `denoise_fix/chroma_denoise.v` 里已有的）：  
  ⚠️ 原因是链路里有 **AWB**，RGB 比例会随光照漂移，直接在 RGB 上卡阈值会“换个灯就失效”。YCbCr 的色度分量对亮度变化鲁棒得多。

### 1.2 时序铁律

- 74.25MHz 预算 **13.33ns，单拍只允许 4 级左右逻辑**，所有乘加必须打拍；
- 行缓存统一用工程内已有的 `denoise_fix/line_delay_ram.v`（`chroma_denoise` 正在用，可直接抄用法）；
- 除法（质心计算）**不要在像素流里做**，放到帧消隐期算（见 2.2）。

### 1.3 公共信号由本人（我）在 top 统一生成并分发

`S_pix_x[10:0] / S_pix_y[9:0]`（de 有效时计数，vsync 清零）+ `S_frame_done`。  
→ 三人都用同一套坐标，**不要各写一份计数器**，否则联调必然对不齐。

### 1.4 交付与集成纪律

- 每人独立目录：`user_source/hdl_source/detect_xxx/`、`track_xxx/`；
- 交付物：`module + testbench + 一句话说明`；
- **top 由本人一人维护**，队友只交模块，避免三人同时改 `design_top_wrapper.v` 冲突；
- 每周三、周日晚上各集成一次。

## 2. 张金艺：扩展2 目标检测与识别

### 2.1 检测流程

```
RGB → YCbCr → 色度双阈值分割 → 二值掩膜 → 连通域标记 → 特征计算 → 分类 → OSD 文字
```

### 2.2 连通域（本项目最难的一块，推荐**游程法**）

全帧 labeling 资源吃不消，用行内 RLE + 行间并查表：

1. **行内**：扫描一行，把连续的“1”合并成游程，记录 `start / end / label`；
2. **行间**：当前行的游程与上一行有重叠则继承 label，多重叠则记录“等价对”；
3. **等价合并**：维护一张深度 32 的等价表（纯寄存器，不用 BRAM），帧末统一解析；
4. **帧末统计**：每 label 的 `面积 Σ1`、`Σx`、`Σy`、`xmin/xmax/ymin/ymax`。

**质心除法怎么处理（关键工程细节）**：  
`cx = Σx / area` 的除数不固定，不能做常数乘法。→ 在 **vsync 消隐期**用移位-减法除法器算：每目标约 10 拍，32 个目标 = 320 拍，而消隐期有数万拍，绰绰有余。

### 2.3 分类特征（区分简单几何体）

| 特征    | 定义        | 典型值                    |
| ----- | --------- | ---------------------- |
| 面积 A  | Σ1        | —                      |
| 宽高比 r | w / h     | 方 ≈1.0                 |
| 填充度 f | A / (w×h) | 圆 ≈0.79，方 ≈1.0，三角 ≈0.5 |
| 色相    | Cb/Cr 均值  | 区分红 / 蓝 / 绿            |

分类规则做成阈值表，目标类型可用拨码或按键切换（红球 / 蓝方块 / 绿三角）。

### 2.4 OSD 文字

- 复用 `osd_char_lib.v`（已有 ASCII 字符）+ `hdmi_mixer.v`；
- 需新增：BCD → ASCII 转换（显示数字）；
- 显示内容：左上角显示类别名 + 目标数量，例如 `RED BALL  N=2`。

## 3. 张铭晨：进阶2 跟踪 + 进阶4 运动检测

### 3.1 目标跟踪（进阶2）

- **输入**：甲输出的目标列表（最多 4 个）：`{valid, cls, cx, cy, xmin, xmax, ymin, ymax, area}`。
- **关联**：最近邻匹配 —— 代价 = 曼哈顿距离 + 面积差 + 类别不一致惩罚；超过门限视为新目标。
- **“框要稳”的三个关键**（这是评分里观感最直接的部分）：
  1. **EMA 平滑**：`box = box + ((new − box) >> 2)`（α=1/4，移位实现，零成本）；
  2. **死区**：`|Δ| < 2 px` 不更新，消除静止时的像素级抖动；
  3. **丢失滞回**：连续 5 帧无匹配才删除框，避免闪烁/断框。
- **摄像头移动**：60fps 下帧间位移小，最近邻足够；再加**速度外推**（`v = pos − pos_prev`，同样 EMA）可明显改善快速移动。
- **OSD**：画框（当前像素坐标与框范围比较，画 2px 边）+ 十字准星 + 坐标数字 `X:0640 Y:0360`。

### 3.2 运动检测（进阶4，帧差法）

```
Y(t) 与 Y(t−1) 差分 → 阈值 → 3×3 形态学(膨胀/腐蚀) → 连通域(复用甲的模块) → 区域框 + 计数
```

**上一帧怎么存（本项目最大的资源坑）**：

- 全帧 Y = 1280×720×8bit = **900KB**，片内 BRAM 放不下；
- 走 DDR 双帧改动太大、风险高（正是花屏高发区），**不推荐**；
- ✅ **推荐降采样**：取 1/4 分辨率（320×180 = 57.6KB，BRAM 可放），运动区域提示按 4×4 块放大显示——运动检测只要“区域提示 + 计数”，不需要像素级精度，完全够用。
- 形态学（膨胀/腐蚀）复用行缓存即可，作用是抹掉孤立噪点、填补空洞。
- 输出：运动区域红框 + `MOTION: N` 计数 + 可选“运动像素占比”进度条。

## 5. 风险与降级方案

| 风险             | 影响                    | 降级方案                                                                      |
| -------------- | --------------------- | ------------------------------------------------------------------------- |
| **人体检测不可行**    | 纯 RTL 无 NPU，CNN 跑不了实时 | 赛题原文是“**简单目标**”，人体不在强制要求内。用红球/色块/几何体演示；若想加“人”，用“肤色 + 运动”启发式当彩蛋（误检高，不进主演示） |

| AWB 漂移导致颜色阈值失效 | 误检/漏检                 | 阈值留按键实时校准；或我提供“AWB 锁定开关”                                                  |

**关于“人体检测与追踪”的诚实建议**：不要把它写进主承诺。评委看的是“框稳不稳、识别准不准、演示流畅不流畅”，一个稳如磐石的红球跟踪，比一个时有时无的人体框得分高得多。把演示脚本设计成“手持红色目标球移动 + 摄像头平移”，效果最可控。

1. 静态目标识别（三类目标各 5 秒）→ 2. 目标慢速移动跟踪（框跟随）→ 3. 摄像头平移（框不跳）→ 4. 遮挡后重现（重锁）→ 5. 运动检测计数（人走过，数字变化）。

## 7. 一条硬经验（本项目血泪教训）

**上板前必须先在 Python 里跑位级仿真（比特级镜像 RTL）**。本项目历史上几个重大 BUG —— 色度降噪的“Y 被除 256 导致近黑”、Verilog 部分选择 `sig[9:0]` 无符号导致蓝黄噪点、`ae_meter` 常量除法位宽 —— 全都是功能级仿真看不出来、位级仿真才抓到的。**功能级“看起来对”不算对**，仿真里要真的按位宽截断、按补码运算。
