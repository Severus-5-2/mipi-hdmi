## 二、`conn_label` 面积优化（v1.5.1）

### 2.1 根因：三个"爆炸放大器"

| # | 位置 | 问题 | 代价 |
|:--|:---|:---|:---|
| ① | `S_IDLE` 的 `for(ii=0..32) root[ii] <= resolve_full(ii)` | **33 份内联**，每份 32 级指针链 | ≈ 数万 LUT（**元凶**）|
| ② | `S_ADDM` 的 `tp_area[root[fs]]` | **双重动态索引**，9 个数组各一套 | 数万 LUT |
| ③ | `acc_sumy` 的 `ev_y * ev_len` | 乘法器 | 吃 DSP |

核心原因：**动态索引的寄存器数组在 FPGA 上无法用 BRAM，只能展开成 n:1 MUX**。

### 2.2 已实施的三刀

#### 第一刀：`S_RSLV` 分时解析（新增状态 `3'd6`）

把 `S_IDLE` 里的 33 份 `resolve_full` 内联改成**分时**（每拍推进 1 级指针，全 NEG+1 个 label 共用 1 套追踪逻辑）：

```verilog
S_RSLV: begin
    if (rk == 7'd0) begin rt <= rq_i[LW-1:0]; rk <= 7'd1; end
    else if (rk == (NEG + 1)) begin
        root[rq_i[5:0]] <= rt;  cmap[...]<=0; rofc[...]<=0;
        tp_area[...]<=0; ...                  // 同步清零
        rk <= 7'd0;
        if (rq_i == NEG[6:0]) begin rq_i<=7'd0; fs<=7'd0; st<=S_ADDM; end
        else rq_i <= rq_i + 7'd1;
    end else begin rt <= eq[rt]; rk <= rk + 7'd1; end
end
```

#### 第二刀：`S_ADDM` 两拍流水（消除双重动态索引）

```verilog
if (adsub == 1'b0) begin          // 拍 1：读 root[fs] / acc_*[fs]（单重索引）
    adx <= root[fs[5:0]];  ad_v <= (acc_area[fs[5:0]] != 20'd0);
    ada_area<=acc_area[fs[5:0]]; ...
    adsub <= 1'b1;
end else begin                    // 拍 2：用 adx 索引 tp_*（单重索引）写回
    if (ad_v) begin tp_area[adx] <= tp_area[adx] + ada_area; ... end
    adsub <= 1'b0;  fs <= fs + 7'd1;
end
```

#### 第三刀（方案 Y）：内部展开深度 `NEG` 32 → 8

```verilog
localparam integer NEG = 8;                   // 展开深度（内部连通域上限）
localparam [LW-1:0] CC_MAX = NEG[LW-1:0];     // 内部 label 分配上限（替代 LBMAX）
```

配套改动：
1. label 分配上限 `LBMAX`(32) → **`CC_MAX`**(8)，共 3 处
2. **`wr_base`/`rd_base` 硬编码 `7'd32` → `NEG[6:0]`** ← 见 §2.3 踩坑
3. FSM 内硬编码 32 全部参数化（`S_ADDM`/`S_SCAN`/`S_OUT` 的 `fs`、`S_DIV` 的 `cid`）
4. `S_SCAN` 加 `sc < CC_MAX` 保护（原 `rofc[sc+1]` 在 sc==NEG 时越界）
5. `S_OUT` 索引统一 `fs[5:0]`
6. **归约树按 NEG 自适应**（`generate if (NEG==8/4/16/2)` 逐级对折）
7. **`verify_conn_label.py` 自动从 RTL 读 NEG** —— 参考模型与 RTL 永远同源

### 2.3 🩸 踩坑记录（两个真 bug）

**bug 1：`7'(NEG+1)` 语法错**
`7'()` 是 SystemVerilog size-cast，TD 的 Verilog-2000 解析器不认 → 改 `(NEG + 1)`。

**bug 2：`wr_base` 越界读 X**
- **现象**：改完 NEG=8 后对拍崩在 `int('x')`，输出里 **1609 行 X 值**。
- **根因**：`rbuf_s/e/l` 声明是 `[0:2*NEG-1]` = **16 项**，但乒乓 bank 基址硬编码 `7'd32`
  → 写读全部越界 → 全 X。
- **定位手法**：拿 `git show HEAD:` 的旧版单独跑同一 TB，确认「旧版 0 个 X / 新版有 X」
  → 锁定是本轮引入。
- **教训**：参数化展开深度时，**凡"第二份"的基址/长度都要跟着参数走**。

| 指标 | 优化前 | 优化后 | 变化 |
|:---|:---:|:---:|:---:|
| 全设计 LUT | 105,584 | **22,717** | **-78%** |
| `u_conn_label` LUT | 77,949 | **1,895** | **-97.6%（降 41 倍）** |
| 综合耗时 | 47 min | **5 min 24 s** | -89% |
| 帧末 FSM 拍数 | ~2,200 | ~1,150 | 更短 |

### 2.5 ⚠ 行为边界（必须告知复用方）

> **同帧内互不连通区域 > `NEG`(=8) 个时，只输出最先出现的 8 个**，其余丢弃（统计也不入桶）。
> 与原 `LBMAX=32` 的降级路径**同语义**，只是门限 32 → 8。

- 演示场景（红球/蓝方块/绿三角 + 少量目标）**最多 3~4 个连通域，远未触及**。
- 后续需要更多时：把 `NEG` 调到 16 + 加对应 `generate` 分支即可。
- **对外接口零改动**：`O_label`/`O_cmp_label`/`O_cmp_cnt` 仍 6 bit，`LABEL_MAX` 宏仍 32
  → 对 `conn_features`/`target_pack`/张铭晨**完全没有影响**。

## 三、logo ROM 转 ERAM（v2 面积优化）

### 3.1 问题定位

优化 `conn_label` 后 LUT 降到 22,717，**仍超 1,501（7.1%）**。门级报告显示新的 LUT 大户：

| 模块 | logic lut | ripple | 合计 | 占比 |
|:---|:---:|:---:|:---:|:---:|
| `u_isp_top`（队长的 ISP） | 2,231 | 2,657 | 4,888 | 21.5% |
| ↳ `u_awb`（含 2 个除法器） | 1,535 | 2,306 | 3,841 | 16.9% |
| `u_ph1p35_324_ddr_wrapper` | 2,400 | 111 | 2,511 | 11.1% |
| `u_hdmi_mixer` | 2,202 | 24 | 2,226 | 9.8% |
| ↳ **`u_anlogic_logo_rom`** | **1,970** | 0 | **1,970** | **8.7%** ← 单个 ROM |
| `u_conn_label` ✅ | 1,833 | 62 | 1,895 | 8.3% |
| `u_chroma_denoise` | 691 | 113 | 804 | |
| `u_demosaic` | 630 | 351 | 981 | |
| `u_hdmi_tx` | 539 | 28 | 567 | |
| `u_box_draw` | 386 | 0 | 386 | |
| `u_conn_features` ✅ | 230 | 0 | 230 | 1.0% |

**结论**：`u_anlogic_logo_rom` 一个 ROM 占 **1,970 LUT（8.7%）**，是 6400 条并行 `case` 比较器
（文件头注释已注明"被综合成 ~13 级 LUT mux 树"）。

### 3.2 处置方案

**改造 `anlogic_logo_rom.v`：组合 `case` → `(* ram_style = "block" *)` 数组 + 同步读。**

```verilog
(* ram_style = "block" *) reg [24:0] mem [0:20426];

integer i;
initial begin
    for (i = 0; i <= 20426; i = i + 1) mem[i] = 25'd0;   // 全清零（= 原 case 的 default）
    mem[5494] = 25'h1d3d4d8;                              // 6387 条有效项
    ...
end

always @(posedge I_clk) O_pixel <= mem[I_addr];           // 同步读，1 拍
```

**为什么时序完全等价**：

| 写法 | 延迟 | 说明 |
|:---|:---:|:---|
| 原：`always @(posedge I_clk) case(I_addr) ... O_pixel = ...; endcase` | 1 拍 | 同步读 |
| 新：`always @(posedge I_clk) O_pixel <= mem[I_addr];` | 1 拍 | 同步读 |

**为什么用满地址空间 0~20426 而不是紧凑重排**：

- 满地址空间 = `hdmi_mixer` 的地址换算**一个字都不用改**（零侵入）。
- 代价：20,427 × 25 bit = 510,675 bit ≈ **24.9 块 ERAM20K**。
- ERAM 改前只用 43/108（39.8%），**余 65 块**，加 25 块后 ≈ 68/108（63%），仍有余量。

**`ram_style` 写法依据**：工程内 `sobel_3x3.v:34` 已在用 `(* ram_style = "block" *)`
（本工程验证过）；TD IP 里用的是 `ram_style="bram"`，若 `block` 不被识别可换。

### 3.3 验证：位级等价对拍

新增 `tb_logo_rom_equiv.v` + `run_verify_logo_rom.sh`：
新旧两版**同时例化**，同一拍给同一地址，**对全部 20,427 个地址逐位比对**。

```
========================================
  [PASS] 全部 20427 个地址逐位一致
========================================
```

覆盖：
- 6387 个有效地址（含 alpha 位与 24bit 颜色）
- **14040 个未初始化地址**（旧 `case` 走 `default=25'd0`，新数组须为 0）
  —— 这一点很关键：`hdmi_mixer` 用 `S_logo_pixel[24]` 判 alpha，未命中须返回 0（透明）。

## 六、时序优化（v1.5.2）：修 `Phy Opt not start`

面积达标（LUT 20,299 / 上限 21,216）后，TD 点 `Phy Opt` 报 **`Phy Opt not start`**。
根因**不是资源，是时序**——`syn_1/flow.status`：

```
Setup : WNS -6386ps   TNS -4262099ps   NUM_FEPS  826
Hold  : WNS   114ps   TNS        0ps   NUM_FEPS    0
```

`gate.timing` 显示 **违例全部落在 `clk1` = `HDMI_PIXEL_CLK`（75 MHz，周期 13.333 ns）**，
其它时钟全部正余量。

### 6.1 最差路径构成（改造前，20 级）

```
u_conn_label/wr_bank_reg → u_conn_label/acc_ymax_reg[*].ce
  Data Path Delay 19.652ns  = cell 6.316ns(32%) + net 13.336ns(68%)
  Max Fanout 128            @ rd_base
```

```
Level 1     : wr_bank_reg → rd_base[3]                      (组合推导!)
Level 2     : DRAM 读 rbuf_e (ramread0_syn_508)
Level 3-5   : resolve3 的 3 级 eq 链        (conn_label.v:125/126/127)
Level 6-14  : eq 链延伸                     (conn_label.v:326)
Level 15    : mux197 (lbl_use)
Level 16-17 : mux197 (acc_area 写译码)
Level 18-19 : ADDER 链 (lt9_syn_50~55)
Level 20    : mux222 → acc_ymax_reg[1].ce
```

**统计**：480 条违例路径里 **478 条是同一条 `wr_bank → acc_*.ce` 路径的各端点**
（10 组 × 10 端点 = 100 条 + 同族），另 2 条是 `detect_color_mask/mult3/4` 的
DSP 内部约束（1 级，无害）。**修好这一条路径，时序基本干净。**

### 6.2 处置（两刀）

**第 1 刀 · `rd_base` 寄存化**（切掉高扇出组合链）

```verilog
wire [6:0] wr_base = wr_bank ? NEG[6:0] : 7'd0;   // 只用于「写」，扇出小，保持组合
reg  [6:0] rd_base;                                // ★ 改寄存器

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)            rd_base <= 7'd0;
    else if (I_frame_done) rd_base <= 7'd0;
    else if (do_swap)      rd_base <= wr_bank ? NEG[6:0] : 7'd0;
end
```

> ⚠ **极性陷阱**：`do_swap` 那拍 `wr_bank <= ~wr_bank`（下一拍生效），
> 故寄存式必须写 **`wr_bank ? NEG : 0`**，不能照抄组合式的 `wr_bank ? 0 : NEG` ——
> 后者晚一拍、读错 bank（实测出 X，156 行）。

**第 2 刀 · `prv_lbl` / `ovl_hit` 插一级流水**（切开「读+解析+比较」与「写译码」）

```verilog
// 第 1 段（组合、到寄存为止）：rd_base_reg → DRAM读 → resolve3 → hit 比较 → 寄存
wire [LW-1:0] prv_lbl_raw [0:NEG-1];
wire          ovl_hit_raw [0:NEG-1];
generate for (gj=0; gj<NEG; gj=gj+1) begin : g_ovl
    wire j_valid = (gj < cnt_rd);
    wire hit_raw = j_valid && (ev_x0 <= rbuf_e[rd_base+gj]) && (ev_x1 >= rbuf_s[rd_base+gj]);
    assign ovl_hit_raw[gj] = hit_raw && ev_valid;
    assign prv_lbl_raw[gj] = hit_raw ? resolve3(rbuf_l[rd_base+gj]) : {LW{1'b0}};
end endgenerate

// ★ 一级流水寄存（事件字段 ev_* 同步打拍，保证下游用同一事件）
reg [LW-1:0] prv_lbl_r [0:NEG-1];
reg          ovl_hit_r [0:NEG-1];
reg          ev_valid_r;  reg [10:0] ev_x0_r, ev_x1_r;  reg [19:0] ev_len_r;
reg [20:0]   ev_sumx_r;   reg [9:0]  ev_y_r;            reg [1:0]  ev_cls_r;

// 第 2 段（组合、从寄存出发）：寄存 → 归约树 → lbl_use → acc 写译码 → acc_ymax.ce
```

### 6.3 配套改动（**缺一不可**）

| 位置 | 改法 | 原因 |
|:---|:---|:---|
| `ev_ok` | `ev_valid` → `ev_valid_r` | 统计/等价/分类统一延后一拍 |
| `eq` / `cls_lbl` / `acc_*` / `rbuf_*` 写 / `cnt_wr` | 门控 `ev_valid` → `ev_valid_r`；数据 `ev_*` → `ev_*_r` | 同拍条件一律读「旧值」，保持一致 |
| `do_swap` | 抑制条件 `!ev_valid` → `!ev_valid_r` | 否则交换那拍事件还在流水寄存器里 → 下拍读的 bank 已换 → 首行首游程静默丢失 |
| `swap_wait` | 行消隐余量 `4'd2` → `4'd3` | 行末游程延后一拍才消费完，多留 1 拍 |
| `frame_end` | 加 `&& !ev_valid` | 行末最后游程那一拍正好是 `ev_valid=1`；若此刻进 FSM，下拍 `ev_valid_r=1` 会把该游程误写进 `rbuf` → 下一帧开局用错 bank → 全帧静默错位 |

### 6.4 踩坑记录（重要教训）

- **`sec_first`「每行首拍」放行 = 误杀同行的第 2 个及以后游程**。
  我一度想用「每行首拍才放行」来抑制跨帧残留事件，结果帧 3 起大量目标丢失
  （帧汇总从 2 个组件掉到 1 个）。
  **正解**：残留事件其实已由 `frame_end` 的 `!ev_valid` + `I_frame_done` 清
  `ev_valid_r` **双重排除**，无需再抑制。教训 —— 抑制条件要按「**本帧**」的语义写，
  不要写成「本行」。
