## 二、一处需收敛：公共坐标计数器（核心问题）

### 2.1 现状：两人各写一份，且写法不同

| | 张铭晨 `pix_coord_gen.v` | 我方 `pix_counter.v` |
|:--|:--|:--|
| 归零时机 | **场消隐期**（vsync 上升沿） | **`I_user` 优先清零**（帧起始） |
| 延时输出 | ✅ 自带 `_1d` / `_2d` | ❌ 无，需下游自建 |
| 输入 | `I_de` / `I_last` / `I_vsync` | `I_de` / `I_user` / `I_last` / `I_vsync` |
| 是否已进 top | ✅ 已集成（他改的） | ❌ 未集成 |

### 2.2 我方发现他自己的文档里点名批评了「user 优先清零」

张铭晨第 5 节原文：

> `hdmi_mixer` 第 327~345 行那份计数器用「user 优先清零」写法，位级审计证明有两个副作用：
> ① 首行（r=0）整行 `S_x` 比真实列号小 1；② 帧首像素采到上一帧残留 `S_y=720`。
> 我的 `pix_coord_gen` 改用**场消隐期归零**，无这两个偏移。**全队请统一用我这一份。**

而我方 `pix_counter.v` 恰好就是「user 优先清零」写法 —— 即他点名的那一类。

### 2.3 ★ 决定：采用张铭晨的 `pix_coord_gen.v`

**理由（三条，均为工程判断，非妥协）：**

1. **他的版本已修掉我方也存在的缺陷。** 「user 优先清零」的首行偏移是真实存在的副作用；场消隐期归零更干净。
2. **他已集成进 top 并通过验证。** 98 文件 elaboration PASS、系统级整帧 PASS（3686405 拍 0 错）。换回我方版本等于让他重验一遍。
3. **他的版本自带 `_1d`/`_2d` 延时输出**，正是下游消费模块需要的，我方版本没有。

### 2.4 ⚠️ 我方发现的一个**新问题**：3 拍流水需要 3 拍延时，但他只给到 2 拍

**这是本次对账最有价值的发现，必须在集成前告诉张铭晨。**

`detect_color_mask.v` 内部流水 **总延迟 = 3 拍**（P1 乘积 / P2 求和移位 / P3 比较），
模块内部已把自己的坐标计数器同步延时 3 拍，保证 `(O_mask, O_pix_x, O_pix_y)` 同拍。

但 `pix_coord_gen.v` 只输出到 **`_2d`（2 拍）**：

```
O_pix_x      → 0 拍
O_pix_x_1d   → 1 拍
O_pix_x_2d   → 2 拍      ← 只到这里
```

**⇒ 若直接把 `S_pix_x_2d` 接进检测模块，坐标会比掩膜早 1 拍。**

**这个坑与我方 D1 抓到的 BUG #1 同源**（时序标志延时链 4 级 vs 坐标 3 级 → 差一拍 → 首像素被丢、整帧错位）。

**解决办法（我方自行处理，不需要他改模块）：**
在检测模块输入端对公共坐标**再补一级寄存器**，凑满 3 拍：

```verilog
// 检测模块内部：公共坐标补 1 拍，凑满 3 拍流水
reg [10:0] S_pix_x_3d;
reg [9:0]  S_pix_y_3d;
always @(posedge clk or negedge rst_n)
    if (!rst_n) { S_pix_x_3d, S_pix_y_3d } <= 0;
    else        { S_pix_x_3d, S_pix_y_3d } <= { S_pix_x_2d, S_pix_y_2d };
```

⇒ **他不需要动 `pix_coord_gen.v`**，我方在模块内自行对齐。

> 若后续 D2+ 出现 4 拍流水的模块，建议他给 `pix_coord_gen` 加一个通用
> `O_pix_x_dly[3:0]` 参数化输出，一次解决「任意拍数对齐」。**此项留作后续建议，非阻塞。**
