## 一、一句话说明

按方案B §2.2 指定的**行内游程（RLE）+ 行间并查表 + 等价表（内部展开深度 `NEG` = 8）**做 **4 连通**连通域标注，
输出「每像素 label 流」与「帧末连通域汇总（面积 / 包围盒 / 质心）」，
供张铭晨的跟踪/关联与队长的区域填充伪彩着色使用。

### 4.1 ★ 内部展开深度 `NEG`

```verilog
localparam integer NEG = 8;    // 纯内部常量，非端口参数
```

| 项 | 说明 |
|:---|:---|
| **含义** | 单帧内**同时**跟踪的连通域上限（等价表 / `eq` / `cls_lbl` / `acc_*` / `tp_*` 全部按此展开） |
| **对外影响** | **无**。`O_label` / `O_cmp_label` / `O_cmp_cnt` 仍是 6 bit，`LABEL_MAX` 宏仍为 32 —— 对 `conn_features` / `target_pack` **零改动** |
| **超出行为** | 同帧内出现 > `NEG` 个互不连通区域时，**最先出现的 `NEG` 个**进入 `O_cmp_*`，其余丢弃（与原 `LBMAX=32` 的降级路径同语义） |
| **历史** | v1.5.1 面积优化 32 → **8**。★ v7.9 曾一度试扩容到 16，**实测代价过大已放弃**（见下），**保持 8** |

**★ v7.9（2026-10-13）：为什么最终「没有」扩容 `NEG`**

现象：现场「**框只能套屏幕靠上部分的物体，物体在下半部分就没有框**」。
因为本模块是「**同帧最多 NEG 个，按扫描顺序先到先得**」，而扫描**从上到下** ⇒
画面上方的噪点先把名额占满 ⇒ **下方真目标拿不到 label**。

**曾按「扩容」思路把 `NEG` 改到 16，TD 实测代价远超预估**：

| 代价项 | 实测结果 |
|:---|:---|
| **slice 占用** | 79.6% → **93.42%**（`conn_label` 4964 LUT / 2907 reg，成**全设计最大模块**） |
| 布局后时序 | **Hold 违例 −266ps / 595 条** |
| 布线 | 违规数**反复涨落**（68 → 2918 → 1180），单次跑 **20+ 分钟**仍未收敛 |

⇒ 余量太小、性价比极低，**已回退到 8**。

### 4.2 ★ 单行游程最小长度 `LMIN`（v7.9 新增 —— 解决「噪声占名额」的根本手段）

```verilog
parameter integer LMIN = 8;    // ★ 带默认值的 parameter（可被 TB 覆盖）
```

| 项 | 说明 |
|:---|:---|
| **含义** | 一行内**连续命中**的长度 < `LMIN` 时，该游程被**整体忽略** |
| **「忽略」的含义** | 不新建 label、不与上一行合并等价、不递增 `lbl_next`、不锁存颜色、不累加统计、不写游程缓冲 |
| **效果** | 噪点**根本不占用 `NEG` 名额** ⇒ 真目标不会被挤出（不再是「先到先得」的牺牲品） |
| **为什么有效** | 噪点在**单行的游程都很短**（几个像素），而目标的游程是**几十~几百像素** |
| **实现落点** | **一处**：在下游消费事件的唯一总门控 `ev_ok` 上加 `ev_long = (ev_len_r >= LMIN)`（`do_swap` 仲裁仍用 `ev_valid_r`，不受影响） |
| **代价** | **一个比较器** —— LUT 可忽略（对比 `NEG` 扩容的 +2800 slice） |
| **取值** | 4~16 可调。调大 → 噪点清得更干净，但目标**窄部**（如三角尖角）会被削；调小 → 更保形状 |

**实测（用 `verify_conn_label.py` 的 11 帧细线条图样直接跑参考模型）**：

| `LMIN` | 每帧组件数 | 合计 |
|:---:|:---|:---:|
| 1（= 不过滤） | [0,1,2,2,1,1,1,8,2,1,8] | 27 |
| 4 | [0,1,2,2,1,1,2,0,2,1,0] | 12 |
| **8（工程默认）** | [0,1,1,0,1,1,2,0,0,1,0] | **7** |
| 12 | [0,0,0,0,0,1,2,0,0,1,0] | 4 |

> ⚠ **TB 覆盖度保护**：单元 TB 的图样是细线条（游程 1~7），若用 `LMIN=8` 会被**全过滤**而丧失覆盖。
> 故 `tb_conn_label.v` / `tb_target_bus.v` / `tb_top_color_chain.v` 例化时**显式传 `.LMIN(1)`**（= 不过滤），
> 而 `verify_conn_label.py` 的参考模型**优先从 TB 读取该覆盖值**，两者永远同源。
> **工程顶层「不传」`LMIN`** ⇒ 用默认值 **8**。
> ⚠ 若现场发现「小目标 / 细长竖直目标被削没了」⇒ 把 `LMIN` 往下调（8 → 6 → 4）。

> ⚠ 归约树按 `NEG` 自适应（`generate` 里 `if (NEG==8/4/16/2)` 分支，逐级对折）。
> ⚠ `verify_conn_label.py` 会自动从 RTL 读 `NEG`、从 TB 读 `LMIN` 覆盖值，参考模型与 RTL 永远同源。

## 五、算法与流水线

```
① 行内游程 RLE      一行内连续的 1 合并成游程 [start,end]，记录 len 与 Σx
② 行间重叠比对       本行游程 vs 上一行游程，4 连通判据：start<=prev_end && end>=prev_start
③ 等价合并          与多个已有 label 重叠 → 取最小值为新 label，其余并入（并查表）
                    label 分配 1 起递增；超过 CC_MAX(=NEG) 则**丢弃该游程**（降级，已如实标注）
④ 统计入桶          按「游程关闭时的 label」累加 area/Σx/Σy/xmin,xmax/ymin,ymax
⑤ 回放输出          下一行回放本行游程，输出每像素 label（指针推进，1 拍/列）
⑥ 帧末 FSM（消隐期） S_RSLV 分时解析等价表 → S_ADDM 两拍归并到根 → S_SCAN 紧凑编号
                    → S_DIV 质心除法 → S_OUT 脉冲输出 → S_CLR 清零
```

其中质心除法用 **31 步移位-减法除法器**（每组件 2 次，共约 128 拍/组件）。

### 时序铁律

- 单拍逻辑 ≤ 4 级；
- 最小 label 归约用**平衡树**（`NEG`=8 → 3 级，不是优先链），保证 74.25 MHz 收敛；
- 除法**不在像素流里做**，放消隐期；
- ★ v1.5.1 面积优化：**帧末解析/归并不再做「N 份并行内联」，一律分时复用**——
  `S_RSLV` 每拍推进 1 级指针（全 `NEG+1` 个 label 共用 1 套追踪逻辑），
  `S_ADDM` 拆两拍消除 `tp[root[fs]]` 双重动态索引。代价是帧末多花几十拍
  （720p60 场消隐约 49,500 拍，占比 < 1%）。

## 六、必须知道的约定

### 6.1 每像素 label 流是 **provisional**（如实说明）

流中输出的是「等价合并后、**当前已知**的最小编号」。原因：连通域的最终编号要等整块区域
扫完（可跨多行）才能定，而像素流是实时的、无法等待未来行。

- **凸形目标**（红球 / 蓝方块 / 绿三角，单行单游程）→ 流与最终结果**完全一致**；
- 环形 / V 形这类「同一行分裂成多游程、之后再合并」的形状 → 流里会短暂出现两个编号。
- **完全确定的结果走 `O_cmp_*`**（帧末算好，跟踪用这个）。

### 6.2 label 流比输入 **晚一行**

行 y 的游程在行 y 期间检出并标注，在行 y+1 期间回放输出。
`O_label_pix_x/y` 输出的是**该 label 真实所属的坐标**，故 `(label, x, y)` 三者自洽，
只是「时间上晚一行」。

⇒ 若要叠伪彩：把视频也延一行（可复用工程内 `line_delay_ram.v`），
或直接用 `O_cmp_*` 的包围盒矩形填色（无延时问题）。

### 6.3 汇总 FSM 在 **场消隐期** 运行，需要足够余量

- **不能用 `I_frame_done` 触发**：VTC 的 `user` 落在**帧首有效像素**（不是消隐期），
  在帧首触发会与下一帧的有效行抢时间、把累加器清掉。
- 本模块**内部检测「最后一行结束」**（`de_fall && I_pix_y == IMG_HEIGHT-1`）触发，
  FSM 天然落在场消隐期。
- **余量需求**（v1.5.1 分时化后）：
  `S_RSLV` (NEG+1)² = 81 拍 + `S_ADDM` 2·(NEG+1) = 18 拍 + `S_SCAN` 9 拍
  + `S_DIV` ≈ 128·NEG = 1024 拍 + `S_OUT` 9 拍 ≈ **1150 拍**。
  720p60 场消隐约 **49500 拍**，占比 **2.3%**，绰绰有余。
  （对比优化前并行内联版约 2200 拍，反而更短。）

### 6.4 连通性固定 **4 连通**

判据只有水平重叠。对角相邻视为两个目标（位级用例已验证）。
8 连通需额外判对角重叠（`±1`），本项目按 4 连通冻结。

### 6.5 最后一行不输出 label

行 719 的游程在帧末清零前来不及回放（回放需要「下一行」），故 label 流**少最后一行**。
`O_cmp_*` 汇总**包含**最后一行（统计在游程关闭时就入桶了）。影响可忽略。

## 七、颜色分类（`O_cmp_cls`）—— 服务于 target_bus 的 `cls`

D4 的「特征计算与分类」里，**形状特征**（面积 / 宽高比 / 填充度）在 `conn_features.v` 与
下游由 `area` + 包围盒**推导**（`w=xmax-xmin+1`、`h=ymax-ymin+1`、`fill=area/(w*h)`），
不必新增位域；而 **`cls`（红/蓝/绿/未分类）** 需要**颜色**，`O_cmp_*` 原本没有，故本次补上。

### 7.1 规则（已与需求方确认）

| 项 | 约定 |
|:---|:---|
| 颜色来源 | 上游 `detect_color_mask.O_mask_r/g/b`，在 top 编码成 2 bit（**红 > 蓝 > 绿** 优先级） |
| 单像素判决 | 同时命中多色 → 按 红 > 蓝 > 绿 取一个（上游编码时定死） |
| 每连通域取色 | **取「该连通域首个被指派时的已知色」**（游程内首个非 `CLS_UNKNOWN` 像素） |
| 等价合并 | 颜色沿并查链**向根传播**（含反向继承），保证链式合并 `eq[5]=3、eq[3]=1` 也传得到最终根 |
| 全程未知 | `O_cmp_cls = 2'b11`（`CLS_UNKNOWN`） |
| 资源 | 32 × 2 bit = **64 FF**（无乘法器、无 BRAM） |

### 7.2 实现要点（为什么不在别的模块算）

`O_cmp_*` 用的是**紧凑编号**（1..cnt），而每像素 label 流用的是 **provisional 编号**，
两者不是一套号（见 §6.1）。颜色必须按**原始 label**（1..32）锁存，只有本模块内部有这个号，
⇒ 颜色状态只能放在本模块。放在 `conn_features.v` 会让它再实现一遍 label 跟踪（状态翻倍且易失配）。

### 7.3 已知前提（如实说明）

**前提：同一连通域内颜色一致**。这正是演示场景（红球 / 蓝方块 / 绿三角各占一种色）。

★ **「红 > 蓝 > 绿」是「单像素编码」的优先级，不是「整块投票」**（2026-10-11 位级实测澄清）：

| 场景 | 行为 |
|:---|:---|
| **单像素**同时命中多色 | 上游编码式取 **红 > 蓝 > 绿**（三阈值在真实数据里其实**互斥**，此项为防御性保留） |
| **两个不同色的大块重叠**（如红块压住蓝块） | 掩膜 3 色取或后**连成同一个连通域**，该块颜色 = **raster 序第一个游程的首个已知色**（谁在上面谁赢），**不做多数投票** |

位级验证（`verify_top_color_chain.py`）专门覆盖了这两类：帧 10~13 是「单像素多通道命中 → 编码优先级」，
帧 6~9 是「大块重叠 → 整块取首游程色」。

| 4~5 | 红+蓝、三色分离 | 多目标独立分类 |
| 6~9 | 两色 / 三色**大块重叠** | 整块取「raster 序首游程色」 |
| **10~13** | **单像素**红∩蓝→红、蓝∩绿→蓝、三色→红、仅绿→绿 | **精确验证编码优先级 红>蓝>绿** |

对拍内容：384 bit 总线**逐位**一致 + `valid_cnt` 一致 + 初始空擂台 `B#0` 全 0。

## 十、已知限制

| 限制 | 影响 | 备注 |
|:---|:---|:---|
| label 流 provisional | 环形/V 形的伪彩会短暂出现两个编号 | 跟踪用 `O_cmp_*`，不受影响 |
| label 流晚一行 / 少最后一行 | 伪彩需同步延一行 | 见 §6.2 |
| 每行 >`NEG`(=8) 游程则丢弃 | 极噪场景会漏目标 | v1.5.1 后由 `NEG` 决定（原 32） |
| **同帧连通域 > `NEG`(=8) 则丢弃** | **同帧同时 >8 个目标时只输出前 8 个** | **v1.5.1 面积优化带来的实际行为边界**；演示场景（3 色 + 少量目标）远未触及。若后续需要更多目标，把 `NEG` 调到 16 并加对应 `generate` 分支即可 |
| 4 连通 | 对角目标算两个 | 已冻结 |
| 混色连通域取首色 | 一块区域内混色时分类可能不准 | 演示目标各占一色，见 §7.3 |
| 大块不同色重叠 → 整块取首游程色 | 红块压住蓝块时整块判红，**不是**按像素投票 | 见 §7.3，位级已覆盖 |
