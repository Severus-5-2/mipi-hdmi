## 4. 正确的话，屏幕上应该看到什么

### 4.1 整体画面（整帧参考图：`sim/system_full.png`）

在摄像头画面（或任意背景）之上，**叠加了 5 个元素**：

| 元素 | 位置（x: 0~1279，y: 0~719） | 颜色 | 说明 |
|:---|:---|:---|:---|
| **B0 红框** | 左上角，外框 (64, 64)–(256, 256) | 纯红 `FF0000` | 方框，**2 px 粗边，框内不填充** |
| **B1 绿框** | 右上角，外框 (1088, 64)–(1279, 256) | 纯绿 `00FF00` | **右边框紧贴屏幕最右一列**，不应缺一段 |
| **B2 蓝框** | 左下角，外框 (64, 464)–(256, 656) | 蓝 `00A0FF` | 与 B0 **关于水平中线 y=360 严格镜像** |
| **B3 黄框** | 屏幕正中，外框 (510, 290)–(770, 430) | 黄 `FFF200` | 框心正好 **(640, 360)** |
| **白色十字准星** | 中心 (640, 360) | 纯白 `FFFFFF` | **臂长 ±16 px、线宽 2 px**，正好落在 B3 正中心 |
| **坐标 OSD** | 左下角 x = 16~112，y = 688~703 与 704~719 | 黄 `FFF200` | 两行 16×16 点阵字：第一行 **`X:0640`**，第二行 **`Y:0360`** |

### 4.2 关键点：这两处必须**互相印证**

> **白色准星压在 B3 黄框的正中心**  ⟺  **左下 OSD 读数是 `X:0640` / `Y:0360`**

准星坐标硬编码为 (640,360)（`box_draw` 的 `SELF_TEST` 分支），OSD 数值也硬编码为 (640,360)
（`osd_coord` 的 `I_x_val/I_y_val`）。所以**只要坐标系统正确，这两件事必然同时成立**；
一旦坐标有偏移，就会出现"准星偏出框心，但 OSD 还写着 0640/0360"这种**互相打架**的画面 ——
这就是 D1 要验的东西。

### 4.3 不应该出现的现象（出现即有问题）

- 框**上方或左侧拖出一大片同色色块**（这是历史上踩过的边框判定 bug 的表现）。
- 框的**边框粗细不均**（有的边 2 px、有的 1 或 3 px）。
- 框整体**右偏/下偏 1~2 px**（准星不在 B3 正中、B1 右边框没贴到 x=1279）。
- 左下角的 `X:0640` 显示成 **`X:0000` 或全部是同一个字符**（这是位宽选错的历史 bug 表现）。
- 画面闪烁、撕裂、整屏花屏（这属于原有链路问题，不是 D1 引入，但会盖住 D1 的现象）。

### 4.4 原有的 OSD 仍应在最上层，互不遮挡

工程原有的叠加不会被动到，上板应该**同时**看到：

| 原有元素 | 位置 | 备注 |
|:---|:---|:---|
| 安路 Logo | 左上 (0,0)–(160,160) | 常驻 |
| 中文信息两行 | 左上 (176, 16) 起 | 帧计数 / AE 增益 |
| 当前模式名 | 右上 (1184, 16) 起 | 彩色 / 灰度 / 二值 / 边缘 |

**几何上互不重叠**（Logo 只到 x=160，信息区从 x=176 起；模式区 x≥1184 且 y≤32，
而 B1 的 y 从 64 才开始）⇒ 不会互相遮盖，两边都能看全。

## 5. 上板自检四条 + 现象对照排查

### 自检四条（全过 = 坐标系统与画框对齐都对）

1. **准星是否在 B3 黄框正中心？**
2. **左下 OSD 是否读 `X:0640` / `Y:0360`？**
3. **B1 右边框是否贴到屏幕最右列 x=1279，没缺一段？**
4. **B0 与 B2 是否关于屏幕水平中线对称（同宽同高、上下镜像）？**

### 现象 → 排查方向

| 现象 | 先查什么 |
|:---|:---|
| 4 个框**完全没出现** | ① `.al` 里 4 个新文件是否都勾了 `UsedInSyn`；② top 里 `u_box_draw`/`u_osd_coord` 是否真被综合（层次树里搜 `box_draw`）；③ `S_box_hit`/`S_coord_hit` 有没有接进 mixer 的 `I_ext_hit` |
| 框**整体右/下偏 1~2 px** | 流水拍数：`box_draw`/`osd_coord` 是"延 2 拍"，与 mixer 的 `S_x_2d`/`S_video_de_2d` 对齐。若接线时多接/少接了一级延时，就会整体偏移 |
| 框**上方/左侧拖出色块** | 边框判定的区间上下界（历史上漏过 `x>=x0` / `y>=y0`） |
| 只有**部分框**出现 | 该框的坐标是否超出 0~1279 / 0~719；B1 的 xmax=1279 是刻意贴边的边界用例 |
| OSD 显示成 `X:0000` 或 6 个相同字符 | 字符序号/位选位宽（历史上把 11 位当 12 位选过 `[11:4]`，选到不存在的位 → 全落 default） |
| OSD 一个字都没有，但框正常 | `pix_coord_gen` 的 `O_frame_done` 是否接进 `osd_coord.I_frame_done`（BCD 每帧才刷新一次） |
| 框位置对、但**颜色串了** | mixer 里叠加的优先级顺序（准星 > B0 > B1 > B2 > B3；外部叠加整体低于 Logo 和中文 OSD） |
| 屏幕上同时有框和原有 OSD，但**框被 Logo 盖住** | 这是**设计如此**（Logo 优先级最高）。B0 在 (64,64)–(256,256)，与 Logo (0,0)–(160,160) 有重叠区，重叠处 Logo 在上 —— 属正常 |
