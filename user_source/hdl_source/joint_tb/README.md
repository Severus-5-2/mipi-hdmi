# joint_tb —— 合板联合验证（我方的检测链 × 张铭晨的跟踪链）

> 创建：2026-10-14 ｜ 适用基线：`Rrrrrr_` @ v8.2（两边功能并到一起的交接版）

## 一、它解决什么问题

两边各自的模块都有单元 TB（我 `detect_zjy/` 10 步、他 7 套），
**但"接在一起还能不能跑"是另一回事** —— 顶层接线错一根、采样时刻差几拍、
坐标约定不同，单元 TB 全都看不出来。

本目录的 `tb_joint_chain.v` 把顶层真实链路的**核心段原样串起来**跑：

```
逐像素场景（程序生成，可自由编排目标）
      │  三通道掩膜 + cls + de + 坐标 + 帧末脉冲
      ▼
mask_despeckle        ← 工程同参数 HALF=4 / KMIN=5 / VER_ROWS=3 / VER_NEED=2
      │  对齐后的 mask / mask_rgb / color / de / 坐标 / 帧末
      ▼
conn_label            ← 工程同参数 MIN_AREA=16 / LMIN=8 / NEG=8
      │  每像素 label + 帧末汇总流
      ▼
conn_features ──► target_bus(4×96) + valid_cnt
      │
      ▼
target_assoc          ← 张铭晨 D5（EMA 平滑 + 漏检保持 + 超时删框）
      │  稳定框 4 槽
      ▼
box_draw              ← 画框（按 cls 上色），第二轮扫描统计命中像素
```

> ⚠ **本 TB 里 `conn_features` 与 `target_assoc` 用的是同一路帧末脉冲**
> （工程里同样是 `S_det_fdone`）—— 这正是冻结表 §1.1 铁律要求的"同源"接法。
> 如果谁把它改成"早 2~13 拍"的那一路，`shape_class` 那种多拍逐槽取数的消费者会静默串帧。

## 二、验证内容（"跑通" + "跑稳"）

| 组 | 场景 | 判据 |
|:---:|:---|:---|
| **A** | 静止双目标（一红一绿）12 帧 | 有效框 = 2、两个目标都能在 4 槽里找到对应框、**连续帧坐标不漂** |
| **B** | 单目标逐帧右移 2px × 14 帧 | 框**跟随**（不是卡死），平滑滞后在容差内 |
| **C** | 出现 6 帧后"消失" | 框**保持几帧**（≤ `MAX_MISS`），超时后**删框** |
| **D** | 连续 6 帧空画面 | **一个框都不该有** ← 最重要验收点 |
| **E** | 混合场景 30 帧（目标增减 + 缓慢移动） | 有效框数随场景变化正确、无 X、无锁死 |
| **F** | 显示侧 | `box_draw` 命中像素的**包围盒 == 框坐标**（画框位置正确） |

### 校验是**顺序无关**的（踩过坑）

`conn_features` 按 **area 降序**排槽（冻结表 §2.3），所以**槽号 ≠ 场景顺序**。
本 TB 用 `find_box(x0, y0, tol)` 在 4 个槽里搜"左上角匹配"的框，
而不是假设"第 0 个目标在槽 0"。

### 两个容差不是随手给的

| 项 | 值 | 依据 |
|:---|:---:|:---|
| `TOL`（静止） | 4 px | 去斑边缘侵蚀（左右各约 1px）+ EMA 残差（收敛需 ~15 帧） |
| `TOL_MV`（运动） | 12 px | `target_assoc` 是一阶 EMA（α=1/4）；**匀速斜坡的稳态滞后 = v×(1-α)/α**，v=2px/帧 ⇒ ≈6px，留一倍余量 |

> 场景之间插了 `idle_frames(8)`：让上一场景的轨迹按 `MAX_MISS` 自然删除，
> 否则旧轨迹会被关联到新目标上（**这是正确行为**，但会把"收敛中"误判成"位置错"）。

## 三、怎么跑

```bash
cd user_source/hdl_source/joint_tb
bash run_joint_verify.sh
```

输出：
- 终端：逐帧摘要 + 最终 `[PASS]` / `[FAIL]`
- `joint_out.txt`：逐帧原始记录（便于事后比对）

需要 Icarus Verilog（`iverilog` + `vvp`）。脚本会自动找常见安装位置，
也可用 `IVERILOG=... VVP=...` 指定。

## 四、边界说明（本 TB 不覆盖什么）

| 不覆盖 | 归谁验 | 说明 |
|:---|:---|:---|
| `motion_detect` / `osd_motion_cnt`（D7/D8） | 张铭晨的 `tb_motion_detect` / `tb_osd_motion_cnt` / `tb_d8_*` | 它们吃的是 24bit RGB 视频流，与本链的"掩膜流"不同源；我方已在他的机器环境复跑通过 |
| `pix_coord_gen`（新版 `O_frame_end`） | `tb_pix_coord_phase` | 相位实测（新版 `fd-df=0`） |
| 真实传感器噪声、ISP 各增益 | 现场下板 | 仿真只能用合成场景 |

## 五、结论口径

- **通过** ⇒ 两边接口（`target_bus` / 帧末脉冲 / 坐标）在 RTL 层面对得上，
  跟踪与画框行为符合双方冻结的语义。
- **不通过** ⇒ 先看 `joint_out.txt` 的逐帧记录定位到哪一组、哪一帧，
  再对照本 README 的判据表判断是 RTL 还是 TB 期望值的问题。
