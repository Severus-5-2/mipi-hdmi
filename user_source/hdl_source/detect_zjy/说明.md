> 项目：MIPI-HDMI 实时视频图像处理系统 · 方案B §2 扩展2（目标检测与识别）
> 负责人：**张金艺** ｜ 目录：`user_source/hdl_source/detect_zjy/`
> 里程碑：**D1 —— 取数 + YCbCr + 阈值掩膜**

## 一、一句话说明

把 `S_video_sat`(RGB888) 转成 YCbCr，按 **Cb/Cr 双阈值**分割出目标颜色的二值掩膜，
并同时输出与掩膜严格对齐的像素坐标 `pix_x / pix_y`，供后续连通域模块使用。

## 四、参数

### 4.1 通用参数

| 参数 | 默认 | 说明 |
|:---|:---:|:---|
| `IMG_WIDTH` / `IMG_HEIGHT` | 1280 / 720 | 必须与视频时序一致（计数器回绕用） |
| `PIPE_DELAY` | 0 | `I_rgb` 相对 `I_de` 的滞后拍数，用法同 `ae_meter.PIPE_DELAY` |
| `PIX_DLY` | 2 | 传入的 `I_pix_x/I_pix_y` 已延时的拍数（接 `S_pix_x_2d` ⇒ 2） |
| `Y_MIN` | 0 | 亮度门限，低于此值不检测（抑制高增益暗部彩色噪点）；`0`=关闭 |
| `USE_ABS_WINDOW` | **0** | `0` = v2 曝光自适应判据（默认）；`1` = 旧的固定绝对窗口（回归对拍用） |

### 4.2 ★ v2 曝光自适应判据参数（`USE_ABS_WINDOW=0` 时生效）

| 参数 | 默认 | 说明 |
|:---|:---:|:---|
| `MAG_TH` | **16** | 饱和度幅度门限 `\|dcb\|+\|dcr\|`，低于此值视为近中性灰、不检测。抗噪↔灵敏度权衡，可调 12~22 |
| `RATIO10` | **13** | 比值判据系数，实现 `\|a\|*10 >= \|b\|*RATIO10`（即比值 ≥ 1.3）。调大更严（抗干扰强但欠曝目标难认），调小更松（易把橙/肤色误判成红） |

**判据公式**（`dcb = Cb−128`、`dcr = Cr−128`）：

```
mag   = |dcb| + |dcr|
红：mag ≥ MAG_TH 且 dcr > 0 且 dcb ≤ 0 且 |dcr|*10 ≥ |dcb|*RATIO10
蓝：mag ≥ MAG_TH 且 dcb > 0 且 dcr ≤ 0 且 |dcb|*10 ≥ |dcr|*RATIO10
绿：mag ≥ MAG_TH 且 dcb < 0 且 dcr < 0
```

### 4.3 旧固定绝对窗口参数（仅 `USE_ABS_WINDOW=1` 时生效，留档）

| 参数 | 默认 | 说明 |
|:---|:---:|:---|
| `RED_CB_LO/HI` | 50 / 125 | 红色 Cb 区间 |
| `RED_CR_LO/HI` | 155 / 255 | 红色 Cr 区间 |
| `BLUE_CB_LO/HI` | 155 / 255 | 蓝色 Cb 区间 |
| `BLUE_CR_LO/HI` | 40 / 125 | 蓝色 Cr 区间 |
| `GREEN_CB_LO/HI` | 20 / 95 | 绿色 Cb 区间 |
| `GREEN_CR_LO/HI` | 0 / 85 | 绿色 Cr 区间 |

> ⚠ 绝对窗口在低曝光下会失效（见 §5.3），**不要**在量产路径里开 `USE_ABS_WINDOW=1`。
> 它只用于「与 D1 基线逐位对拍」和「排查判据切换引入的问题」。

## 五、算法与流水线

### 5.1 YCbCr 换算（与 `chroma_denoise.v` 位级一致）

```
Y  =  77R + 150G +  29B            → (x + 128) >>> 8
Cb = -43R -  85G + 128B  + 128     → ((x + 128) >>> 8) + 128
Cr = 128R - 107G -  21B  + 128     → ((x + 128) >>> 8) + 128
```

`+128` 是四舍五入、`>>>` 是算术右移 —— 两者都不能省，否则有 1 LSB 系统性偏移。
常数乘法由综合器自动优化成移位加网络，**不消耗 DSP**。

### 5.2 流水线（3 拍，单级 ≤4 级逻辑）

| 拍 | 内容 |
|:---:|:---|
| P1 | 9 个常量乘积寄存 |
| P2 | 3 项求和 + 四舍五入 + 算术右移 + 偏置 128 |
| P3 | **先限幅**，再色相判据比较 → 掩膜 |

`I_de/I_vsync/I_hsync/I_user/I_last` 与公共坐标 `I_pix_x/I_pix_y` 在模块内部同步延时 3 拍，
**下游拿到的 `(O_mask, O_de, O_pix_x, O_pix_y)` 一定是同一个像素**，不需要再自己算延时。

### 5.3 ★ 为什么从「固定绝对窗口」换成「曝光自适应判据」（2026-10-11）

**现场症状**：低曝光下「检测不全」「掩膜/小绿块时有时无」「框只在物体或摄像头移动时显现」。

**根因**（已用 `common_base/sim_lowlight_mask.py` 定量复现）：
目标变暗 ⇒ 三通道同比例缩小 ⇒ 色差 `(R−Y)`、`(B−Y)` 同比例缩小
⇒ 饱和色朝中性灰 `(Cb,Cr)=(128,128)` **收敛** ⇒ 逃出固定绝对窗口。

实测崩溃点（目标亮度百分比降到多少就检不出）：

| 目标 | 实测 YCbCr 漂移 | 崩溃点 |
|:---|:---|:---:|
| 红球 | `Cb 104→123`，`Cr 198→142` | 35% |
| 蓝块 | `Cb 198→142`，`Cr 117→126` | 35% |
| 绿块 | `Cb 82→119`，`Cr 69→116` | **60%** |

绿块最先崩（且最严重），所以现场看到的是「绿的最先没框」。

**处置**：换成以 `(128,128)` 为原点的**方向 + 幅度 + 比值**判据（见 §4.2）。
方向判据对「整体亮度缩放」天然免疫（缩放不改变 `dcb/dcr` 的符号与比值），
只留 `mag` 一个门限挡暗部噪点。

**定量收益**（同一套随机模型）：

| 目标亮度 | 旧固定窗口（红/蓝/绿） | v2 自适应（红/蓝/绿） |
|:---:|:---:|:---:|
| 60% | 1.00 / 1.00 / **0.00** | 1.00 / 1.00 / 1.00 |
| 35% | **0.14 / 0.11 / 0.00** | 1.00 / 1.00 / 1.00 |
| 28% | 0 / 0 / 0 | 1.00 / 0.99 / 1.00 |
| 干扰色误判率 | 5.7% | **1.1%** |
| 交叉错色率 | — | **0.00%** |

> 附带收益：颜色卡里的「棕」(128,80,48) 在旧窗口被判成红（误判），v2 正确排除。

**现场调参指引**：
- 光仍不足（暗目标检不出）→ `MAG_TH` 往下调 `16 → 14 → 12 → 10`
- 误检太多（橙色/肤色被当红）→ `MAG_TH` 往上调 `16 → 18 → 20`，或 `RATIO10` 调大 `13 → 15`

### 6.2 ⚠ `PIPE_DELAY` 怎么定

本模块假定 `I_rgb` 与 `I_de` **同拍**。但工程里 `S_video_sat` 比 `S_hdmi_de` 晚了
「gamma 1 拍 + `chroma_denoise` N 拍 + `sat_enhance` 2 拍」。若直接接 `S_hdmi_de`，
请把总差值填进 `PIPE_DELAY`（容差 0~15）。

**先上板看掩膜对不对时，建议这么标定**：拿一个纯色目标放画面正中，
设 `PIPE_DELAY=0` 跑一次，若掩膜整体右移/下移了 k 个像素，把 `PIPE_DELAY` 加 k 再试。

纯软件模型（不走 RTL），复现「低曝光检测不全」并扫 `MAG_TH` / `RATIO10` 参数。

### 7.1 位级仿真抓到的两个真 BUG（已修，留档）

| # | 现象 | 根因 | 修法 |
|:---:|:---|:---|:---|
| 1 | 首像素被丢、整帧错位一个像素 | 时序标志用了 **3bit 移位寄存器再取 `[2]`**，等于串了 4 级寄存器，比坐标/掩膜的 3 级多一拍 | 时序标志改 **2bit 移位取 `[1]`**，与坐标延时严格对齐 |
| 2 | **纯红/纯蓝判不出来** | `q_cb/q_cr` 值域可达 **256**（`+128` 偏置取整所致），而阈值上限只能填 255，`256 <= 255` 不成立 ⇒ 最饱和的纯色被漏掉 | **先限幅到 0~255 再做阈值比较**（原来是拿未限幅值比较） |

> 这两个都是「功能级看起来对、位级仿真才现形」的典型 —— 印证了方案B §7 的那条血泪经验。

### 7.2 验证脚本自身的坑（2026-10-11，留档）

改 v2 判据时，`verify_color_mask.py` 的参数解析把 **RTL 头部注释里的文字**
`（仅 USE_ABS_WINDOW=1 时生效）` 当成真实参数值，导致模型走错分支、误报。

> 教训：**解析 RTL 必须先剥注释**。现在脚本里 `header` 会先过
> `re.sub(r"//[^\n]*", " ", ...)` 与块注释剥离再匹配参数。
