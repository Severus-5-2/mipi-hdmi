> 项目：MIPI-HDMI 实时视频图像处理系统 · 方案B §2 扩展2（目标检测与识别）

## 一、一句话说明

把 `S_video_sat`(RGB888) 转成 YCbCr，按 **Cb/Cr 双阈值**分割出目标颜色的二值掩膜，
并同时输出与掩膜严格对齐的像素坐标 `pix_x / pix_y`，供后续连通域模块使用。

## 四、参数

### 4.1 通用参数

| 参数 | 默认 | 说明 |
|:---|:---:|:---|
| `IMG_WIDTH` / `IMG_HEIGHT` | 1280 / 720 | 必须与视频时序一致（计数器回绕用） |
| `PIPE_DELAY` | 0 | `I_rgb` 相对 `I_de` 的滞后拍数，用法同 `ae_meter.PIPE_DELAY` |
| `PIX_DLY` | 2 | 传入的 `I_pix_x/I_pix_y` 已延时的拍数（接 `S_pix_x_2d` ⇒ 2） |
| `Y_MIN` | 0 | 亮度门限，低于此值不检测（抑制高增益暗部彩色噪点）；`0`=关闭 |
| `USE_ABS_WINDOW` | **0** | `0` = v2 曝光自适应判据（默认）；`1` = 旧的固定绝对窗口（回归对拍用） |

### 4.2 ★ v2 曝光自适应判据参数（`USE_ABS_WINDOW=0` 时生效）

| 参数 | 默认 | 说明 |
|:---|:---:|:---|
| `MAG_TH` | **48** | 饱和度幅度门限 `\|dcb\|+\|dcr\|`，低于此值视为近中性灰、不检测。抗噪↔灵敏度权衡，可调 32~64<br>★ 2026-10-12 由 16 加严到 48（现场"满屏绿点/乱跳"，见 §5.4） |
| `RATIO10` | **13** | 比值判据系数，实现 `\|a\|*10 >= \|b\|*RATIO10`（即比值 ≥ 1.3）。调大更严（抗干扰强但欠曝目标难认），调小更松（易把橙/肤色误判成红） |
| `G_AXIS_TH` | **20** | ★ 2026-10-12 新增：**绿判据双轴门限**，要求 `\|dcb\| ≥ G_AXIS_TH` **且** `\|dcr\| ≥ G_AXIS_TH`。绿在 (Cb,Cr) 平面是对角方向，真绿两轴同向同量级；传感器噪声两轴独立、常一轴大一小 ⇒ 被挡。可调 12~28；置 0 退回旧绿判据 |

**判据公式**（`dcb = Cb−128`、`dcr = Cr−128`）：

```
mag   = |dcb| + |dcr|
红：mag ≥ MAG_TH 且 dcr > 0 且 dcb ≤ 0 且 |dcr|*10 ≥ |dcb|*RATIO10
蓝：mag ≥ MAG_TH 且 dcb > 0 且 dcr ≤ 0 且 |dcb|*10 ≥ |dcr|*RATIO10
绿：mag ≥ MAG_TH 且 dcb < 0 且 dcr < 0 且 |dcb| ≥ G_AXIS_TH 且 |dcr| ≥ G_AXIS_TH
```

| `BLUE_CB_LO/HI` | 155 / 255 | 蓝色 Cb 区间 |

## 五、算法与流水线

### 5.1 YCbCr 换算（与 `chroma_denoise.v` 位级一致）

```
Y  =  77R + 150G +  29B            → (x + 128) >>> 8
Cb = -43R -  85G + 128B  + 128     → ((x + 128) >>> 8) + 128
Cr = 128R - 107G -  21B  + 128     → ((x + 128) >>> 8) + 128
```

`+128` 是四舍五入、`>>>` 是算术右移 —— 两者都不能省，否则有 1 LSB 系统性偏移。
常数乘法由综合器自动优化成移位加网络，**不消耗 DSP**。

### 5.2 流水线（3 拍，单级 ≤4 级逻辑）

| 拍 | 内容 |
|:---:|:---|
| P1 | 9 个常量乘积寄存 |
| P2 | 3 项求和 + 四舍五入 + 算术右移 + 偏置 128 |
| P3 | **先限幅**，再色相判据比较 → 掩膜 |

`I_de/I_vsync/I_hsync/I_user/I_last` 与公共坐标 `I_pix_x/I_pix_y` 在模块内部同步延时 3 拍，
**下游拿到的 `(O_mask, O_de, O_pix_x, O_pix_y)` 一定是同一个像素**，不需要再自己算延时。

### 5.3 ★ 为什么从「固定绝对窗口」换成「曝光自适应判据」（2026-10-11）

**现场症状**：低曝光下「检测不全」「掩膜/小绿块时有时无」「框只在物体或摄像头移动时显现」。

**根因**（已用 `common_base/sim_lowlight_mask.py` 定量复现）：
目标变暗 ⇒ 三通道同比例缩小 ⇒ 色差 `(R−Y)`、`(B−Y)` 同比例缩小
⇒ 饱和色朝中性灰 `(Cb,Cr)=(128,128)` **收敛** ⇒ 逃出固定绝对窗口。

实测崩溃点（目标亮度百分比降到多少就检不出）：

| 目标 | 实测 YCbCr 漂移 | 崩溃点 |
|:---|:---|:---:|
| 红球 | `Cb 104→123`，`Cr 198→142` | 35% |
| 蓝块 | `Cb 198→142`，`Cr 117→126` | 35% |
| 绿块 | `Cb 82→119`，`Cr 69→116` | **60%** |

绿块最先崩（且最严重），所以现场看到的是「绿的最先没框」。

**处置**：换成以 `(128,128)` 为原点的**方向 + 幅度 + 比值**判据（见 §4.2）。
方向判据对「整体亮度缩放」天然免疫（缩放不改变 `dcb/dcr` 的符号与比值），
只留 `mag` 一个门限挡暗部噪点。

**定量收益**（同一套随机模型）：

| 目标亮度 | 旧固定窗口（红/蓝/绿） | v2 自适应（红/蓝/绿） |
|:---:|:---:|:---:|
| 60% | 1.00 / 1.00 / **0.00** | 1.00 / 1.00 / 1.00 |
| 35% | **0.14 / 0.11 / 0.00** | 1.00 / 1.00 / 1.00 |
| 28% | 0 / 0 / 0 | 1.00 / 0.99 / 1.00 |
| 干扰色误判率 | 5.7% | **1.1%** |
| 交叉错色率 | — | **0.00%** |

> 附带收益：颜色卡里的「棕」(128,80,48) 在旧窗口被判成红（误判），v2 正确排除。

**现场调参指引**（★ 2026-10-12 更新，门限已整体加严）：

> ⚠ **改门限请改 `common_base/common_defs.vh` §5b 的宏**（`` `MAG_TH `` / `` `RATIO10 `` / `` `G_AXIS_TH ``）——
> 顶层例化引的就是这三个宏，改一处即生效。下表列的是模块 `parameter` 默认值，**必须与宏保持一致**
> （`verify_color_mask.py` 会自动交叉校验，不一致直接报错）。

- **画面仍有零星绿点 / 误检多** → `MAG_TH` 往上调 `48 → 56 → 64`；绿点集中在小块则同时调大 `G_AXIS_TH` `20 → 24 → 28`
- **目标检不出 / 框出不来** → `MAG_TH` 往下调 `48 → 40 → 32`（每降一档误命中约升 5~10 倍，慎用）
- **橙色/肤色被当红** → `RATIO10` 调大 `13 → 15`

> **★ 2026-10-12 血泪教训（务必看）**：只改模块 `parameter` 默认值是**没用的** ——
> 顶层 `design_top_wrapper.v` 例化时显式传参会**覆盖**默认值。曾经出现「改了 48 却仍在跑 16」，
> 导致掩膜满屏噪声 → `conn_label` 连通域数超出 `NEG=8` → **真目标被挤出目标列表 → 框出不来**。
> 现已统一改为引 `common_defs.vh` 的宏，并加了自动交叉校验。


### 5.4 ★ 为什么门限从 16 加严到 48 + 绿判据加双轴门限（2026-10-12）

**现场现象**（2026-10-12 下板）：画面上**密布绿色小点**（掩膜叠加），人 / 墙 / 帘子上全是，
且**逐帧乱跳**，完全淹没真实目标。注意这与 5.3 的"检测不全"是**相反方向**的问题。

**根因**：传感器色度噪声 `dcb`/`dcr` 近似独立正态 `N(0, σ)`。旧判据里
「`mag ≥ 16` 且 `dcb < 0` 且 `dcr < 0`」这**一个绿的象限判据**：

| σ（色度噪声标准差） | 被误判成目标的像素比例 |
|:---:|:---:|
| 8 | **12.9%** |
| 10 | **20.2%** |
| 12 | **25.9%** |

红/蓝判据有比值约束（要求方向性强），误命中低得多；**绿只有象限 + 幅度，是主要漏口**。
噪声还让边缘像素在门限附近随机跨越 ⇒ 逐帧乱跳。

**处置**（两道同时加严）：

1. `MAG_TH` 16 → **48**
2. 绿判据新增**双轴门限** `G_AXIS_TH = 20`：`|dcb|` 与 `|dcr|` 必须**各自**达标。
   绿在 (Cb,Cr) 平面是对角方向（纯绿 dcb:dcr ≈ -85:-107），真绿两轴同向同量级；
   而噪声两轴独立，常常一轴大、一轴小 ⇒ 被挡住。

**实测效果**（`sim_lowlight_mask.py --noise`，可复现）：

| 配置 | σ=8 | σ=10 | σ=12 | σ=15 |
|:---|:---:|:---:|:---:|:---:|
| 旧 `MAG_TH=16` 绿无轴限 | 12.93% | 20.18% | 25.89% | 31.81% |
| **新 `MAG_TH=48` 绿轴≥20** | **0.00%** | **0.04%** | **0.27%** | **1.47%** |

**代价**（目标可检出的最低亮度）：纯色 红 10%→28%、绿 9%→26%、蓝 11%→32%。
⇒ **35% 亮度三色仍 100% 可检**（v2 当初的设计承诺不变）；25% 以下极暗场景会漏，
属「宁缺毋滥」的取舍。拟真色（如红球 (200,60,60)，mag=94）余量充足，正常光照下无影响。

> 调参方向：现场仍见零星绿点 → `MAG_TH` 加档；暗场景检不出 → `MAG_TH` 降档（误命中会同步上升）。

### 5.5 ★★ 真正的破局点：水平去斑 `mask_despeckle.v`（2026-10-12 最终方案）

**三轮排查的结论：靠调判据门限无解。**

| 门限 | 后果 |
|:---|:---|
| `MAG_TH=16`（最初） | 掩膜满屏噪声 → `conn_label` 同帧连通域数 **4.6 万**个 → 挤爆 `NEG=8` → 真目标全被挤掉 → **无框** |
| `MAG_TH=48`（中途） | 噪声压下去了，但**物体内部也检不出**（绿物体要 60% 亮度）→ 只有边缘过冲的像素能过 → **只检测到边缘、断断续续加框** |
| `MAG_TH=24` + 去斑 ✅ | 物体内部检得出（绿 30% 亮度）**且**噪声被清掉 → **正确** |

**为什么门限救不了？** 因为瓶颈是 `conn_label` 的 **`NEG=8`**：
「同一帧最多 8 个连通域，先到先得」，而**噪点每个孤立点自成一个连通域**。

**破局点：噪声是孤立散点，目标是成片区域。**
在检测与连通域之间插入 `mask_despeckle.v`：
**① 水平窗**（左右各 `HALF` 个像素，窗内命中数 ≥ `KMIN`）
**② 垂直多数投票**（跨 `VER_ROWS` 行，至少 `VER_NEED` 行通过）

> **★★ 最终参数（2026-10-12 深夜定稿，几经反复，过程留档）**
>
> 这个模块的参数调了三轮，每一轮的失败都很有教育意义：
>
> | 轮次 | 参数 | 结果 | 教训 |
> |:---|:---|:---|:---|
> | 1 | `H4 K5` | 纯噪声 → 0 个 ✅，但**背景仍有密集小点** | 没考虑噪声是**水平相关**的 |
> | 2 | `H5 K10`（调严） | 噪声压住了，但会**把斑点状物体打碎** | 严过滤对"实心块"无损，对"有纹理的物体"是灾难 —— 仿真：物体命中密度 0.7 时，400×250 的物体被打得只剩 **67 px** |
> | 3 | **`H4 K5` + 垂直 `2/3` 投票** ✅ | 两者兼顾 | **二维信息才是关键**：水平窗挡不住水平相关噪声，垂直投票可以 |
>
> **为什么垂直投票有效**：`chroma_denoise` 只在**水平方向**平滑色度，
> 所以噪声在垂直方向**仍然独立**。跨 3 行做 2/3 表决，
> 噪声要连续 2 行同列都命中才会存活（概率极低），而目标在垂直方向是连续的。
>
> **仿真对比（整帧 1280×720，数值 = 连通域数 / 最大连通域面积）**：
>
> | 场景 | 单看水平 `H4 K5` | **+ 垂直 `2/3` 投票** |
> |:---|:---:|:---:|
> | 纯噪声（σ=8 相关3 / σ=10 相关5） | 0 | **0** ✅ |
> | 物体命中密度 0.7 | 35 个碎片 / 89095 | **5 个 / 96194** ✅ |
> | 物体命中密度 0.8 | 26 个碎片 / 97481 | **2 个 / 99322** ✅ |
>
> （连通域数必须 ≤4 才不挤占 `conn_label` 的 `NEG=8` 名额；目标面积几乎无损）
>
> **实现代价**：2 个 **1-bit 行缓存**（复用工程已有的 `line_delay_ram.v`）+
> 一个 3 输入加法器。列对齐由「本行延 2 拍、第 1 行延 1 拍、第 2 行不延」精确保证，
> TB 实测**输出包围盒与输入块完全一致**（x[20..39] y[3..7]）。



**实现**：独立模块，放在 `detect_color_mask` 与 `conn_label` 之间。
用「预延时 EQ + 公共延迟链」保证掩膜/颜色/de/坐标/帧末**严格同像素**，
总延迟 `LAT = HALF+1+DCH = 7` 拍。资源约 200 寄存器 + 30 LUT，**可忽略**。

> ⚠ **加新文件后必须在 TD GUI 里 `Source → Add Source...` 加入工程**，否则综合报模块找不到。

**现场调参**（都在 `common_defs.vh §5b` + `mask_despeckle` 参数）：

| 现象 | 怎么调 |
|:---|:---|
| 仍有零星绿点 | 去斑加严：`KMIN` `5 → 6 → 7`；或 `HALF` `4 → 5 → 6` |
| 目标被削得太狠/小目标丢失 | 去斑放宽：`KMIN` `5 → 4` |
| 目标漏检（暗场景） | `MAG_TH` `24 → 20 → 16` |

### 6.2 ⚠ `PIPE_DELAY` 怎么定

本模块假定 `I_rgb` 与 `I_de` **同拍**。但工程里 `S_video_sat` 比 `S_hdmi_de` 晚了
「gamma 1 拍 + `chroma_denoise` N 拍 + `sat_enhance` 2 拍」。若直接接 `S_hdmi_de`，
请把总差值填进 `PIPE_DELAY`（容差 0~15）。

**先上板看掩膜对不对时，建议这么标定**：拿一个纯色目标放画面正中，
设 `PIPE_DELAY=0` 跑一次，若掩膜整体右移/下移了 k 个像素，把 `PIPE_DELAY` 加 k 再试。

### 7.1 位级仿真抓到的两个真 BUG（已修，留档）

| # | 现象 | 根因 | 修法 |
|:---:|:---|:---|:---|
| 1 | 首像素被丢、整帧错位一个像素 | 时序标志用了 **3bit 移位寄存器再取 `[2]`**，等于串了 4 级寄存器，比坐标/掩膜的 3 级多一拍 | 时序标志改 **2bit 移位取 `[1]`**，与坐标延时严格对齐 |
| 2 | **纯红/纯蓝判不出来** | `q_cb/q_cr` 值域可达 **256**（`+128` 偏置取整所致），而阈值上限只能填 255，`256 <= 255` 不成立 ⇒ 最饱和的纯色被漏掉 | **先限幅到 0~255 再做阈值比较**（原来是拿未限幅值比较） |

> 这两个都是「功能级看起来对、位级仿真才现形」的典型 —— 印证了方案B §7 的那条血泪经验。

### 7.2 验证脚本自身的坑（2026-10-11，留档）

改 v2 判据时，`verify_color_mask.py` 的参数解析把 **RTL 头部注释里的文字**
`（仅 USE_ABS_WINDOW=1 时生效）` 当成真实参数值，导致模型走错分支、误报。

> 教训：**解析 RTL 必须先剥注释**。现在脚本里 `header` 会先过
> `re.sub(r"//[^\n]*", " ", ...)` 与块注释剥离再匹配参数。
