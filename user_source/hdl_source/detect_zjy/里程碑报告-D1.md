## 三、技术要点

### 3.1 为什么走 YCbCr（方案B §1.1 的落实）

链路里有 **AWB**，RGB 三通道比例随光照漂移 —— 直接在 RGB 上卡阈值「换个灯就失效」。
色度 Cb/Cr 对亮度变化鲁棒，因此颜色分割放在 YCbCr 域。

### 3.2 位级一致性

换算与 `chroma_denoise.v` **完全一致**（含 `+128` 四舍五入与 `>>>` 算术右移）：

```
Y  =  77R + 150G +  29B            → (x + 128) >>> 8
Cb = -43R -  85G + 128B  + 128     → ((x + 128) >>> 8) + 128
Cr = 128R - 107G -  21B  + 128     → ((x + 128) >>> 8) + 128
```

常数乘法由综合器优化为移位加网络，**不占 DSP**。

### 3.3 流水线（3 拍）

| 拍 | 内容 | 逻辑级数 |
|:---:|:---|:---:|
| P1 | 9 个常量乘积寄存（并行） | ≤4 |
| P2 | 3 项求和 + 舍入 + 右移 + 偏置 | ≈4 |
| P3 | 先限幅 → 双阈值比较 → 掩膜 | ≈3 |

`I_de/I_vsync/I_hsync/I_user/I_last` 与自建 `x/y` 计数器在模块内同步延时 3 拍，
**下游拿到的 `(O_mask, O_de, O_pix_x, O_pix_y)` 必为同一像素**。

## 五、⚠ 位级仿真抓到并修复的 2 个真 BUG（重点）

功能级仿真看不出来、只有位级对拍才现形 —— 印证方案B §7 的血泪经验。

### BUG-1 「差一拍」：首像素被丢、整帧错位

- **现象**：仿真第一行输出是 `x=1, Y=1`，即 x=0 的首像素凭空消失，后面全部错位一格。
- **根因**：时序标志用了 **3 bit 移位寄存器再取 `[2]`**，等于串了 **4 级**寄存器；
  而坐标/掩膜路径只有 **3 级**（`x_cnt → d3_x_0 → d3_x_1 → O_pix_x`）。
  时序比重/数据晚一拍 ⇒ 输出有效窗口整体平移。
- **修法**：时序标志改 **2 bit 移位 + 取 `[1]`**，正好 3 级，与坐标严格对齐。
- **教训**：延时链要**数寄存器个数**，不是数位移位数。「掩膜对了、de 晚一拍」这种错最阴。

### BUG-2 限幅顺序错：纯红/纯蓝判不出来

- **现象**：纯红 (255,0,0) 的 `mask_r = 0`，纯蓝 (0,0,255) 的 `mask_b = 0` —— 最饱和的目标色反而漏检。
- **根因**：`q_cb / q_cr` 的理论值域是 **[1, 256]**（`+128` 偏置 + 舍入所致），
  而阈值参数上限只能填 **255**。原实现拿**未限幅**的 q 去比较，
  `256 <= 255` 不成立 ⇒ 高饱和色被判为「不命中」。
- **修法**：**先限幅到 0~255，再做阈值比较**。
- **教训**：定点流水里，「输出限幅」和「比较用值」必须想清楚谁先谁后；
  值域核查要算到**偏置之后**，不能只看理论区间。
